01

核心原则

五条规则，防止优化器偏移方向、自我刷分或引入退化。

01

可归因的修改

每轮处理一个可独立验证的问题；按需修改入口及相关参考、脚本和资产。先保存精确基线，保留已有改动。

02

双重评估

文字修订核对能力和引用；流程改变比较代表性案例；脚本改动执行相关回归。验证深度与影响相称。

03

棘轮机制

有改善证据且能力、正确性和权限无回退才保留。失败只恢复本轮差异；提交和已提交回滚按 Git 授权执行。

04

独立评分

核心用途、授权或复杂恢复改变时使用可用独立评审；不可用时说明限制。实际执行记 full_test，仅推演记 dry_run。

05

人在回路

用户选择逐阶段审核时保留检查点；已授权连续优化无需逐项确认。展示差异、证据和未验证项，发布、付费和 Git 动作须有对应授权。

03

优化循环

从确认范围到交付证据的五个阶段。检查点遵循用户选择；小修订不强制完整评测矩阵。

0 初始化

范围与基线

确定可维护源、已有改动和授权范围，保存可恢复基线；相关历史记录按需读取。

  1. 确认范围：全部 Skill 还是用户指定子集
  2. 核对当前宿主启用目录和可维护 source tree，排除无关资产
  3. 为精确目标保存基线，Git 分支与提交按任务授权执行
  4. 需要批量对比时才按评测约定保存 results.tsv
0.5 设计

测试提示词工程

针对实际变化选择案例；措辞修订核能力与引用，脚本修复使用最小回归。

  1. 阅读每个 SKILL.md，理解其声明的能力
  2. 按影响选择典型、边界或不应触发的相关案例
  3. 需留档时保存到任务产物目录，未经要求不加入 Skill 或 Git
  4. 用户指定此审核点时等待批准；已授权连续优化继续
1 基线

可比较基线

对齐旧版和候选输入、资源与观察标准。需量化时才给分，缺失数据注明未测量。

  1. 列出能力和具体问题，保留触发、恢复、授权和产物合同
  2. 先比较旧版与候选；需判断Skill本身收益时再加无Skill基线
  3. 实际执行并检查结果为 full_test，推演为 dry_run；独立性另行记录
  4. 使用量化评测时记录实际口径，不以估算伪装观测
  5. 展示基线与限制，仅在用户指定审核点等待确认
2 优化

证据驱动的修订

按真实缺陷及影响排序，修复一个可验证的问题；评分或轮次不构成继续修改的理由。

  1. 确认可复现问题或能力冲突及其影响
  2. 提出一项具体改进并明确验证与恢复方式
  3. 修改必要入口或支持资源；Git 动作按对应授权执行
  4. 做相关回归；复杂用途、授权或恢复变化使用可用独立复核
  5. 有改善证据且无能力、正确性或权限回退才保留，否则只恢复本轮差异
  6. 展示差异与证据；按所选审核模式继续或等待
3 报告

总结与指标

汇总修改或保留理由、能力落点、验证和限制；仅有量化评测时报告分数和收益。

  1. 统计总实验次数、保留次数、回滚次数和测试模式
  2. 交付精确路径、差异、能力覆盖和恢复方式
  3. 列出已确认改进及其可复核证据
  4. 按需归档脱敏记录，标明实测、推演与未验证项

05

为什么需要
双重评估

单看结构无法判断 Skill 是否真正好用。单看效果无法判断它为何失败。

传统方法

纯结构审查

  • 检查 frontmatter 是否存在且格式正确
  • 验证步骤是否有编号和描述
  • 确认文件路径和引用是否有效
  • 无法检测 Skill 是否真正提升了输出质量
  • 无法检测看似正确实则产生差结果的误导性指令
  • 无法检测弊大于利的过度约束
Auto Skill Optimizer

双重评估

  • 结构评分捕捉格式、完整性和可读性问题
  • 实测执行揭示真实场景下的行为影响
  • 基线对比衡量 Skill 是增值还是减值
  • 可用独立复核检查核心用途、授权和复杂恢复变化
  • 测试提示词设计确保评估针对真实用户场景
  • Dry-run 推演记录预期行为，不能当作实测收益

概念映射

autoresearch 的核心抽象如何转化为 Skill 优化。同一台机器，不同的领域。

Autoresearch Skill Optimizer 实现细节
研究论文草稿 SKILL.md 文件 入口与相关参考、脚本、模板、资产共同承载能力；仅改本轮所需文件。
评估指标 可选量化评测 可采用100分、结构60/效果40等可比口径；不强制评分。
实验循环 证据驱动修订 确认问题、修改、验证、保留或精确恢复。问题解决即交付，预算上限按任务约定。
版本控制 精确基线与恢复 保留可恢复证据；Git 分支、提交与已提交回滚按任务授权执行。
自动化评估 子 Agent 测试执行 按影响选择可用独立审查或测试；隔离旧版与候选，必要时补无Skill基线。
人类审查关卡 用户指定检查点 用户选择逐阶段审核时等待；已授权连续优化不重复确认。
探索 vs 利用 按证据调整范围 无改善时停止微调。结构重写须有具体依据，超出授权时先给可审核范围。
实验日志 results.tsv 带时间戳的记录：commit 哈希、Skill 名称、新旧分数、保留/回滚状态、评估模式。
