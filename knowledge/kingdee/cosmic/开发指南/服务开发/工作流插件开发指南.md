# 工作流插件开发指南

> 来源: https://vip.kingdee.com/knowledge/24194, https://vip.kingdee.com/knowledge/272105401284413440, https://vip.kingdee.com/article/146459, https://vip.kingdee.com/article/146461
> 日期: 2026-04-12
> 标签: 工作流, IWorkflowPlugin, 审批流, 流程插件, 参与人插件

---

## 摘要
金蝶云苍穹工作流插件通过实现 IWorkflowPlugin 接口，在流程运行的各个环节（参与人计算、条件判断、节点进入/离开等）注入自定义业务逻辑，支持 Java 插件和 KingScript 脚本两种开发方式。

## 适用版本
- 金蝶云苍穹 V5.0+
- KingScript 轻脚本支持需 V7.0.11+

## 核心概念

### 插件接口定义

```java
package kd.bos.workflow.engine.extitf;

public interface IWorkflowPlugin extends ITaskPlugin {
    // 具体方法见下方方法说明表
}
```

### 插件方法一览

| 方法 | 说明 | 典型场景 |
|------|------|----------|
| `calcUserIds` | 返回参与人 ID 列表 | 自定义审批人计算逻辑 |
| `hasTrueCondition` | 返回 true/false 判断条件 | 条件分支路由 |
| `notify` | 节点进入时正向执行 | 进入节点时修改单据状态 |
| `notifyByWithdraw` | 节点离开/撤回时执行 | 撤回时恢复单据状态 |
| `formatFlowRecord` | 格式化审批记录显示 | 自定义审批记录内容 |

### 插件场景分类

| 场景 | 支持类型 | 可定义数量 |
|------|----------|-----------|
| 参与人插件 | Java、脚本 | 只能一个 |
| 条件规则扩展 | Java、脚本 | 只能一个 |
| 流程控制扩展 | Java、脚本、实体操作 | 可多个 |
| 节点控制扩展 | Java、脚本、实体操作 | 可多个 |
| 自动节点 | Java、脚本、实体操作 | 可多个 |

### AgentExecution 参数对象

所有工作流插件方法都通过 `AgentExecution` 获取流程上下文：

| 方法 | 返回类型 | 说明 |
|------|----------|------|
| `getBusinessKey()` | String | 当前单据的业务 ID |
| `getEntityNumber()` | String | 单据实体编码 |
| `getCurrentTaskId()` | Long | 当前工作流任务 ID |
| `getProcessDefinitionId()` | Long | 流程定义 ID |
| `getProcessInstanceId()` | Long | 流程实例 ID |
| `getCurrentFlowElement()` | WorkflowElement | 当前节点信息 |
| `getVariable(String)` | Object | 获取流程变量值 |
| `setVariable(String, Object)` | void | 设置流程变量值 |
| `getCurrentTaskResult()` | TaskResult | 当前任务执行结果（决策项） |
| `getStartUserId()` | Long | 流程发起人 ID |
| `getCurrentApprover()` | List<Long> | 当前节点审批人列表 |

## 详细内容

### 一、参与人插件

当标准的参与人设置（按角色、按部门、按指定人）不满足需求时，通过参与人插件自定义审批人逻辑。

#### 1.1 Java 插件实现

```java
package com.example.workflow;

import kd.bos.dataentity.entity.DynamicObject;
import kd.bos.orm.query.QFilter;
import kd.bos.orm.query.QCP;
import kd.bos.servicehelper.BusinessDataServiceHelper;
import kd.bos.workflow.engine.extitf.IWorkflowPlugin;
import kd.bos.workflow.engine.extitf.AgentExecution;
import kd.bos.workflow.engine.extitf.WorkflowElement;

import java.util.ArrayList;
import java.util.List;

/**
 * 参与人扩展插件：根据单据金额确定审批人
 */
public class AmountApproverPlugin implements IWorkflowPlugin {

    @Override
    public List<Long> calcUserIds(AgentExecution execution) {
        // 获取单据信息
        String businessKey = execution.getBusinessKey();
        String entityNumber = execution.getEntityNumber();

        // 加载单据数据
        DynamicObject bill = BusinessDataServiceHelper.loadSingle(
            businessKey, entityNumber
        );

        // 根据金额确定审批人
        java.math.BigDecimal amount = bill.getBigDecimal("amount");
        List<Long> approvers = new ArrayList<>();

        if (amount.compareTo(new java.math.BigDecimal("10000")) > 0) {
            // 金额超过10000，需要总经理审批
            approvers.add(getManagerUserId());
        } else {
            // 金额10000以内，部门经理审批
            approvers.add(getDeptManagerUserId(bill));
        }

        return approvers;
    }

    private Long getManagerUserId() {
        // 查询总经理用户ID
        DynamicObject manager = kd.bos.servicehelper.QueryServiceHelper.queryOne(
            "bos_user", "id",
            new QFilter[]{new QFilter("number", QCP.equals, "manager001")}
        );
        return manager != null ? manager.getLong("id") : null;
    }

    private Long getDeptManagerUserId(DynamicObject bill) {
        // 根据单据所属部门查询部门经理
        DynamicObject dept = bill.getDynamicObject("org");
        // 具体查询逻辑根据业务实现
        return dept != null ? dept.getLong("id") : null;
    }
}
```

#### 1.2 KingScript 脚本实现

```javascript

        var entityNumber = execution.getEntityNumber();
```

### 二、条件规则插件

在条件分支节点中，通过插件实现复杂的条件判断逻辑。

```java
/**
 * 条件规则扩展插件：根据单据类型和金额判断走哪条分支
 */
public class BillConditionPlugin implements IWorkflowPlugin {

    @Override
    public boolean hasTrueCondition(AgentExecution execution) {
        String businessKey = execution.getBusinessKey();
        String entityNumber = execution.getEntityNumber();

        DynamicObject bill = BusinessDataServiceHelper.loadSingle(
            businessKey, entityNumber
        );

        // 获取当前节点信息
        WorkflowElement<?> flowElement = execution.getCurrentFlowElement();
        String nodeNumber = flowElement.getNumber();

        // 根据节点编号和单据数据判断条件
        if ("condition_high_amount".equals(nodeNumber)) {
            java.math.BigDecimal amount = bill.getBigDecimal("amount");
            return amount.compareTo(new java.math.BigDecimal("50000")) > 0;
        }

        return false;
    }
}
```

### 三、节点控制插件（监听器/自动节点）

在节点进入或离开时执行业务逻辑。

#### 3.1 节点进入时执行

```java
/**
 * 节点控制插件：审批通过后修改单据状态
 */
public class ApprovalNotifyPlugin implements IWorkflowPlugin {

    /**
     * 节点进入，正向执行
     * 触发时机：进入节点时、离开节点时、任务处理时
     */
    @Override
    public void notify(AgentExecution execution) {
        String businessKey = execution.getBusinessKey();
        String entityNumber = execution.getEntityNumber();

        // 获取当前任务执行结果
        // getCurrentTaskResult() 可获取决策项编码、名称、类型和审批意见
        Object taskResult = execution.getCurrentTaskResult();

        // 加载单据并修改状态
        DynamicObject bill = BusinessDataServiceHelper.loadSingle(
            businessKey, entityNumber
        );

        if (bill != null) {
            // 修改单据自定义字段
            bill.set("custom_approval_status", "approved");
            bill.set("custom_approve_time", new java.util.Date());

            // 保存单据
            kd.bos.servicehelper.SaveServiceHelper.save(
                new DynamicObject[]{bill}
            );
        }
    }

    /**
     * 撤回时执行
     * 当审批被撤回时，恢复单据状态
     */
    @Override
    public void notifyByWithdraw(AgentExecution execution) {
        String businessKey = execution.getBusinessKey();
        String entityNumber = execution.getEntityNumber();

        DynamicObject bill = BusinessDataServiceHelper.loadSingle(
            businessKey, entityNumber
        );

        if (bill != null) {
            bill.set("custom_approval_status", "withdrawn");
            kd.bos.servicehelper.SaveServiceHelper.save(
                new DynamicObject[]{bill}
            );
        }
    }
}
```

#### 3.2 操作类型插件

除了 Java 和脚本，节点还可以直接调用单据上的操作（如提交、审核等）：

- 正向执行时调用指定操作
- 撤回时需设置对应的撤回操作
- 注意操作与单据状态的一致性

### 四、流转记录格式化插件

自定义审批记录的显示内容。

```java
/**
 * 流转记录格式化插件
 * 修改审批记录中的显示文本，如添加审批人职位信息
 */
public class FlowRecordFormatPlugin implements IWorkflowPlugin {

    @Override
    public String formatFlowRecord(AgentExecution execution) {
        Long userId = execution.getStartUserId();
        WorkflowElement<?> flowElement = execution.getCurrentFlowElement();
        String nodeName = flowElement.getName();

        // 获取用户信息（含职位）
        DynamicObject user = BusinessDataServiceHelper.loadSingle(
            userId, "bos_user"
        );
        String userName = user.getString("name");

        // 返回格式化后的记录文本
        return String.format("[%s] %s 已完成审批", nodeName, userName);
    }
}
```

### 五、插件注册

#### 5.1 注册路径

- **流程控制插件**：【流程服务云】→【工作流服务】→【设计中心】→【流程设计】→【流程控制】→【流程插件】
- **节点插件**：【流程设计】→【人工/审批/会审设置】→【插件】

#### 5.2 注册方式

1. **Java 插件**：将完整包名输入"插件类"文本框
2. **KingScript 脚本**（V7.0.11+）：在脚本选择界面注册、启用和管理轻脚本
3. **旧 KDE 脚本**：通过 KDE 平台新增脚本，选择"流程插件"类型

#### 5.3 节点控制的细分时机

| 时机 | 说明 |
|------|------|
| 正常进入 | 流程正常流转到该节点 |
| 驳回进入 | 从后续节点驳回到该节点 |
| 跳转进入 | 通过跳转方式进入该节点 |
| 计算参与人时 | 计算节点参与人时执行 |
| 离开节点时 | 任意决策项都会执行 |
| 任务处理时 | 可根据决策项定义不同插件 |

### 六、工作流跳转节点示例

通过插件获取后续节点信息并跳转：

```java
public class JumpNodePlugin implements IWorkflowPlugin {

    @Override
    public void notify(AgentExecution execution) {
        // 获取所有节点信息
        Long processDefinitionId = execution.getProcessDefinitionId();

        // 使用 WorkflowServiceHelper 获取流程所有节点
        // 然后判断当前节点及后续节点，执行跳转逻辑
        WorkflowElement<?> currentElement = execution.getCurrentFlowElement();
        String currentNodeId = currentElement.getId();
        String currentNodeName = currentElement.getName();

        // 设置流程变量，控制后续流转
        execution.setVariable("jumpTarget", "targetNodeNumber");
    }
}
```

## 注意事项

1. **状态一致性**：工作流只负责调用单据"操作"，操作内容由单据决定。如果插件调用逻辑与单据状态逻辑冲突，会导致插件执行失败
2. **撤回处理**：设置正向执行插件时，也要设置对应的撤回插件，确保撤回后状态正确
3. **参与人插件唯一性**：参与人和条件规则插件只能定义一个，不能多个
4. **流程变量**：自 V5.0.002 起，脚本插件支持传递插件参数
5. **脚本选择**：V7.0.11+ 支持新 KingScript 轻脚本，推荐使用新脚本开发平台
6. **错误排查**：流转日志中的"业务逻辑错误"通常是插件调用与单据状态冲突导致
