# Frontend Development

> Cross-platform Agent Skill · 在项目实际入口完成前端代码与验证。

## 触发与输入

- **明确需求**。根据预期行为、验收条件和现有项目实现前端功能。小范围且可逆的界面细节沿用项目惯例，记录影响结果的假设。
- **UI 美工稿**。从用户指定的设计图、源稿或样式规范直接实现。图中缺少的窄屏布局、键盘操作和控件状态，按已知业务与项目组件补全。涉及核心视觉或业务结果的歧义先核对。
- **UI 设计交接**。已有交互稿、中英双语规范与可调参数时，核对同一选定版本。按[设计输入与实现规则](references/design-input.md)将其落实到代码。明确需求和美工稿均可直接作为开发输入。

## 工作流程

1. 从真实入口定位路由、共享组件、主题、客户端状态和接口。沿用项目技术栈与已有组件，按目标环境和官方文档核对新增 Web 能力及依赖的兼容性。
2. 将选定的布局、字级、颜色和组件状态映射到项目主题变量、组件属性及样式。按目标宽度还原内容顺序和主要操作。组件采用可访问的语义，落实适用的焦点、键盘和触控反馈。
3. 涉及取数或提交时，按现有接口约定接入。按任务覆盖加载、空结果、校验、错误、重试等实际分支。连续操作或请求乱序会影响结果时，验证最终界面和业务状态一致。
4. 有动效时实现确认的效果，沿用项目时长和缓动变量。可重复触发的过渡支持从当前状态中断或反向。核对退场、触摸反馈和减少动态效果下的结果。
5. 从正常入口走通关键流程。用目标尺寸、代表性数据和受影响状态核对渲染结果，运行项目已有的相关检查。

## 开发输出与验收

开发任务交付可维护的前端代码、实际使用入口和验证结果。代码审查交可定位的问题与影响。交互稿、中英双语规范和可调设计参数由 UI 设计环节交付，供有设计交接的开发任务使用。

## 授权与失败处理

已获开发授权且输入足够时直接实施。用户要求先审核时交对应的技术方案或代码审查。视觉取舍仍待定且会改变实现时，将该项交回 UI 设计环节或向用户核对，再落实相关代码。兼容性导致效果或行为受限时，指出目标环境、受影响项和实际验证结果。
