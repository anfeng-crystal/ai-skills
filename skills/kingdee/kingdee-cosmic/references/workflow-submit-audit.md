# 提交、自动审核与流程寻址

仅在提交后自动审核、紧接提交调用审核，或提示“单据已在流程中流转，不能审核”时读取。该提示也可能来自异步寻址尚未结束，不能单凭提示认定已有活动流程，更不能据此清理流程记录。

## 先确定适用分支

复用目标版本、升级来源、单据参数和当前流程记录证据；版本未知时只保留候选解释，不更改单据状态或工作流配置。

| 目标条件 | 官方文章描述的行为 |
| --- | --- |
| V8.0 新客户，开启“提交后自动审核” | 跳过流程寻址，直接自动审核 |
| V8.0 由旧版本升级，开启上述单据参数 | `workflow.submit.isSubmitAndAudit=false` 默认保留旧寻址逻辑；`true` 才采用跳过寻址逻辑 |
| V9.0 新老客户，开启上述单据参数 | 先寻址；匹配到流程则进入工作流并阻断自动审核，未匹配到流程才自动审核 |

V8.0 的该内置参数不控制新客户的行为。V9.0 的“未匹配到流程”不能扩大解释为引擎异常、超时也应自动审核。未开启自动审核时仍要检查正常寻址链路；提交后立即手动审核的时序冲突在文中仍列为遗留问题，不能声称升级后全部消失。

## 代码与诊断

- 命名单据问题先核对该单据的活动/历史流程存在性，再结合提交、寻址和审核的时间证据判断。数据库取证沿用 `kingdee-sql-and-data` 的只读范围；没有流程图或没有当前活动记录，不能单独证明从未寻址。
- 对代码连续执行提交和审核的场景，文章给出的候选是在**提交操作**的 `OperateOption` 中设置 `setVariableValue("preaddressing", String.valueOf(true))`。先核验目标 SDK、操作参数传递链和版本适用性；文章没有给该变量逐补丁支持矩阵，不能复制到所有提交入口、自动重试审核或当成绕过审批的通用开关。
- 根据已确认需求处理“进入审批流”和“自动审核”两条互斥结果，保持单据状态与流程状态各自的含义。验收涵盖是否命中流程、自动审核是否启用，以及实际使用的提交入口；不以固定等待时长代替寻址完成证据。
- 参数变更、流程修改和真实提交/审核各按本次授权范围执行。只读诊断或 Skill 优化不包含这些动作。
