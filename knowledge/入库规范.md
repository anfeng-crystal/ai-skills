# AI 知识库入库规范

> 版本: 1.0
> 日期: 2026-04-15
> 适用范围: `/Users/anfeng/AI/knowledge` 下所有活跃知识库

---

## 1. 定位
- 活跃知识库只保存长期稳定、可复用、可检索、可追溯的知识。
- 原始过程材料、任务流水、交付记录、验证日志、工单、临时结论和沟通记录归入 `/Users/anfeng/AI/archive`。
- MCP 服务、依赖包、运行日志和服务配置归入 `/Users/anfeng/AI/mcp`。
- 活跃知识文档必须能回答固定问题：适用什么场景、依据是什么、如何使用、边界在哪里、失败时如何判断。

## 2. 目录边界
| 目录 | 用途 | 可写入内容 |
|---|---|---|
| `/Users/anfeng/AI/knowledge` | 活跃知识 | 规则、指南、API 参考、案例模式、模板、索引 |
| `/Users/anfeng/AI/archive` | 流程归档 | 工单、交付物、执行记录、验证日志、任务过程、原始材料 |
| `/Users/anfeng/AI/mcp` | MCP 资产 | MCP 服务、依赖、配置、服务日志 |

## 3. 来源等级
| 可信等级 | 来源 | 使用规则 |
|---|---|---|
| 官方 | 官方文档、官方社区、产品手册、公开 API 文档 | 可作为主依据 |
| 本地验证 | 本地依赖、源码、SDK、数据库、编译或测试结果 | 可作为当前环境依据 |
| 项目经验 | 已完成项目中可复用的稳定结论 | 必须保留可追溯来源 |
| 待确认 | 未被官方、本地依赖或项目验证支撑的判断 | 只能标注为待确认，不得写成确定规则 |

## 4. 可入库内容
- 稳定规则：平台约束、业务口径、配置边界、版本差异、安全要求。
- 可复用方法：固定步骤、输入输出、失败条件、注意事项、反例。
- 可复用案例：场景、问题模型、判断规则、推荐写法、适用边界。
- API 与代码示例：方法签名、参数说明、最小示例、依赖前提、失败边界。
- 索引和导航：分类入口、搜索关键词、相关知识链接。

## 5. 禁止入库内容
- 实施过程说明、排查路径、验证经过、修改经过、尝试失败、任务背景、交付口径。
- 工单状态、派发记录、评分过程、沟通记录、会议纪要、执行流水。
- 构建日志、运行日志、截图流水、临时命令输出、未清洗原文。
- 无来源的 AI 总结、未验证却写成确定结论的代码说明、无法复用的一次性项目材料。
- 密钥、账号、租户敏感地址、客户隐私、临时 token、内部沟通原文。

## 6. 过程性表述处理
| 表述类型 | 处理方式 |
|---|---|
| “本次”“此次”“这里改为” | 改写为稳定规则、适用场景或边界条件 |
| “为了修复”“为了兼容”“经过排查” | 改写为问题模型、原因机制或失败条件 |
| “最终采用”“先...再...最后...” | 改写为固定步骤或推荐做法 |
| “验证经过”“交付结果”“用户确认” | 归入 `/Users/anfeng/AI/archive` |

## 7. 正式文档结构
```markdown
# 标题

> 来源: 官方文档 / 本地依赖 / 项目源码 / 已验证案例
> 日期: YYYY-MM-DD
> 标签: 标签1, 标签2, 标签3
> 适用范围: 产品 / 版本 / 模块 / 场景
> 可信等级: 官方 / 本地验证 / 项目经验 / 待确认

---

## 摘要
一句话说明本文可复用的知识结论。

## 适用场景
说明何时使用、何时不使用。

## 前置条件
列出版本、依赖、配置、权限或运行环境要求。

## 固定规则
写长期有效的规则、约束、边界和判断口径。

## 推荐做法
写可复用步骤、模板、参数说明或代码模式。

## 失败条件
写不可用场景、常见错误、风险和回退判断。

## 示例
只保留能说明规则的最小示例。

## 相关链接
链接到官方资料、本地源码依据、同类知识或索引。
```

## 8. 清洗规则
- 原始材料先放入归档区，再提炼为活跃知识。
- 测试验收材料只提炼验证门禁、兼容性结论、失败模式和检查方法。
- 开发最佳实践只保留问题模型、判断条件、推荐写法、反例和适用边界。
- 需求材料只有具备行业复用价值时进入活跃知识库。
- 迭代记录默认进入归档区；可提炼为规范变更、设计原则或稳定清单。

## 9. 入库门禁
- 来源门禁：至少有一个可靠来源；无来源内容不得进入活跃知识库。
- 稳定性门禁：三个月后仍有复用价值；只服务单次任务的材料归档。
- 过程性门禁：过程性表述必须改写为规则、边界、案例模式或固定步骤。
- 验证门禁：写“已验证”必须能对应编译、测试、联调、源码或官方依据；未验证只能写“待验证”。
- 安全门禁：敏感信息必须脱敏；无法脱敏的材料不得入库。
- 索引门禁：新增、移动、清洗、删除文档后必须更新根索引、分类索引或搜索索引。

## 10. 入库检查清单

- [ ] 来源、日期、标签、适用范围、可信等级齐全。
- [ ] 摘要能说明可复用结论。
- [ ] 正文不含任务流水、沟通记录或交付口径。
- [ ] 示例代码有适用前提和失败边界。
- [ ] 未验证内容标注为待确认或待验证。
- [ ] 敏感信息已脱敏。
- [ ] 索引和相关链接指向真实文件。
