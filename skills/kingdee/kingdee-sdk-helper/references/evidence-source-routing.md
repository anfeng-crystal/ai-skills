# SDK/API 证据来源路由

## 优先级

| 等级 | 来源 | 可确认内容 |
|---|---|---|
| 1 | 目标项目解析后的依赖 JAR、同版本 Javadoc、反射/编译结果 | 当前项目可见类、方法签名和编译兼容性 |
| 2 | 当前 skill 的 SDK 索引及其可核验版本/来源 | 索引中明确存在的类、签名和注释 |
| 3 | 目标项目已编译通过的源码引用 | 该项目版本中的用法；不能自动外推到其他版本 |
| 4 | 金蝶官方产品文档、官方 SDK 文档或官方示例 | 文档明确标注版本范围内的候选/确认信息 |
| 5 | 金蝶社区文章、项目片段、论坛回答、反编译摘要 | 仅作为检索候选，必须回到 1-4 级复核 |
| 6 | 无来源或第三方转载 | 不用于确认签名 |

同级冲突时以目标项目实际依赖和编译证据为准。源码只存在但未挂载、未编译或未在目标版本出现时，输出“候选”而不是“已确认”。

## 社区和项目资料

- 记录来源类型、标题/文件、平台版本、发布日期或提交版本；缺一项就标记证据缺口。
- 社区资料可以提供类名、关键词和场景线索，但不能直接确认方法签名、默认值、事务语义或生产可用性。
- 项目实现属于项目事实，不得写成标品能力；跨项目复用前重新核对依赖和元数据。
- 反编译资料只有在来源、许可证和用途允许时用于定位，不复制实现，不把推断写成官方契约。
- 需要联网核验最新文档时转 `web-access`，只用官方一手技术来源确认；无法访问时保留“未确认”。

## 输出状态

- `confirmed-project`：目标项目 JAR/编译已确认。
- `confirmed-index`：当前 SDK 索引已确认，但目标项目版本尚未确认。
- `official-versioned`：官方、带版本资料确认。
- `candidate-community`：社区或项目片段只提供候选。
- `unconfirmed`：证据不足或来源冲突。

输出类全名、完整签名、证据状态、证据来源和版本缺口；不要把多个来源拼成一个不存在的签名。
