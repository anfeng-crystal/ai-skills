# 样式变更规则

## 先确定载体

| 载体 | 执行入口 |
|---|---|
| 元数据控件的宽高、颜色、边距、布局、可见、锁定等属性 | 本 skill，按控件精确 profile 修改 |
| 页面扩展 `index.js/index_m.js`、CSS、运行时 DOM 样式 | `kingdee-frontend-script` |
| 独立 KDApi 自定义控件工程 | `kingdee-custom-control` |

## 元数据样式

- 必须定位实际页面和控件；同名字段在 PC 表单、PC 列表和移动布局可能是不同节点。
- 属性必须在目标节点、祖先有效节点或精确实际 profile 中出现；值形态必须与生产标准观察一致。
- 只新增属性时按 profile 的实际子节点顺序插入，不能整树重排。
- 样式修改不能带出身份、绑定、父容器或其他终端布局变化。
- 继承问题优先恢复或建立正确目标层覆盖，不用 CSS 掩盖错误元数据。

## JS/CSS

JS/CSS 不属于元数据库模板合同。转交后仍需用真实页面/控件标识、稳定 DOM、PC/移动入口、生命周期和清理规则验证；不能凭截图猜编译类名，也不能让 CSS 承担权限、字段类型、必录、锁定或操作状态语义。
