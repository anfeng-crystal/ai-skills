## 1. 基本原则
- 本规范只补充金蝶云苍穹专项要求；通用入库门禁遵守上级规范。
- 金蝶技术结论必须可追溯到官方资料、本地依赖、项目源码或已验证案例。
- 当前项目依赖和目标租户版本优先于市场资料、旧经验和通用 Java 写法。
- 平台能力判断必须先看配置能力，再判断插件、脚本或扩展代码。

## 5. 内容结构
正式金蝶文档使用以下结构：

```markdown
## 摘要
一句话说明可复用结论。

## 适用场景
说明平台模块、对象类型、插件类型或业务场景。

## 前置条件
说明版本、依赖、元数据、字段、权限或配置要求。

## 配置优先判断
说明元数据、界面规则、业务规则、工作流规则、操作配置、模板配置是否可覆盖。

## 固定规则
写平台约束、API 规则、事务边界、字段口径和版本差异。

## 推荐做法
写固定步骤、代码模式、配置模式或查询方式。

## 失败条件
写不可用场景、常见错误、风险和回退判断。

## 示例
保留最小可复用代码、配置或参数示例。

## 相关链接
链接到官方资料、API 参考、同类指南或索引。
```

## 6. 代码和 API 示例
- Java 示例必须标注依赖前提、适用版本和失败边界。
- 插件示例必须说明继承类、事件方法、挂载点和事务阶段。
- API 示例必须写明方法签名、参数含义、返回值和调用限制。
- 报表示例必须说明分页、排序、DataSet 关闭规则和只读边界。
- KingScript 示例必须符合脚本运行上下文，不得写成 Java 类模板。
- 代码注释只写职责、业务口径、平台约束、边界条件和长期有效但不直观的原因。

## 7. 配置优先
- 单据、基础资料、动态表单、列表、移动端、工作流、打印、导入导出、报表能力先判断配置是否可完成。
- 配置可覆盖时，知识文档必须优先记录配置路径和限制条件。
- 插件、脚本和扩展代码只记录配置无法覆盖的兜底场景。
- 配置能力不确定时标注“待确认”，不得写成确定结论。

## 8. 清洗边界
- 测试验收材料提炼为验证门禁、兼容性结论、失败模式和检查方法。
- 开发最佳实践提炼为问题模型、判断条件、推荐写法、反例和适用边界。
- 需求材料只有具备行业复用价值时进入 `行业/` 或 `领域/`。
- 迭代记录默认归档；可提炼为规范变更、Skill 设计原则或稳定检查清单。
- 工单、交付物、构建日志、执行记录、评分过程和任务派发表不得进入活跃知识正文。

## 9. 索引维护
- 新增、移动、清洗、删除或重命名文档后，必须更新相关索引。
- 根索引更新 `README.md`。
- API 文档更新 `API参考/API参考汇总.md`。
- 检索关键词更新 `社区资源/搜索索引/search_index.md`。
- 行业文档更新对应行业索引或 `行业/README.md`。
- 领域文档更新对应 `领域/**/INDEX.md` 或 `领域/README.md`。
- 索引链接必须指向真实存在的文件。

## 10. 入库门禁
- 来源齐全：官方资料、本地依赖、项目源码或已验证案例至少命中一类。
- 版本明确：确定版本写具体版本；不确定写待确认。
- 配置优先：涉及平台能力必须写配置能力判断。
- 过程清洁：正文不含实施过程、排查路径、验证经过、交付口径或沟通记录。
- 技术可用：代码、API、字段和事件不凭记忆生成。
- 安全合规：敏感信息脱敏，无法脱敏的材料不得入库。
- 索引同步：相关索引已更新，链接可打开。
