# MED-001 门诊挂号登记单 - 开发最佳实践

> 归档时间：2026-04-12 | 需求：MED-001 | 评分：8.63/10

## 一、插件开发核心模式

### 1.1 表单插件（AbstractBillPlugIn）关键事件使用

| 事件 | 用途 | 本需求中的应用 |
|------|------|---------------|
| afterCreateNewData | 新建单据时设置默认值 | 默认就诊日期(今天)、单据状态(暂存)、支付状态(未支付) |
| afterLoadData | 加载数据后初始化 | 重新设置医生字段过滤条件 |
| propertyChanged | 字段值变更联动 | 科室→医生联动、身份证→年龄、号源类型→费用 |
| beforeDoOperation | 操作前拦截校验 | 保存/提交前格式校验 |

### 1.2 基础资料联动过滤（标准写法）
```java
BasedataEdit doctorEdit = this.getControl("med_doctor");
QFilter deptFilter = new QFilter("med_belong_dept", QCP.equals, deptId);
doctorEdit.addServiceFilter(deptFilter);
```

**关键要点：**
- 使用 `addServiceFilter` 而非 `setFilter`（后者会覆盖已有过滤）
- 联动变更时先 `setValue(null)` 清空下级字段，再重设过滤条件
- `afterLoadData` 中也要设置过滤条件（编辑态重新加载时需要）

### 1.3 操作插件自定义 Validator
```java
public class RegisterSaveOpPlugin extends AbstractOperationServicePlugIn {
    @Override
    public void onPreparePropertys(PreparePropertysEventArgs e) {
        // 必须声明需要加载的字段，否则 dataEntity 取值为 null
        e.getFieldKeys().add("med_doctor");
    }

    @Override
    public void onAddValidators(AddValidatorsEventArgs e) {
        e.addValidator(new CustomValidator());
    }
}
```

**关键要点：**
- `onPreparePropertys` 必须声明所有后续用到的字段
- Validator 中使用 `QueryServiceHelper.queryCount()` 而非查全量再 `.length`
- 批量校验使用 `for (ExtendedDataEntity entity : this.getDataEntities())`

### 1.4 列表脱敏处理
```java
@Override
public void processRowData(String pluginName, List<Map<String, Object>> rowDatas) {
    for (Map<String, Object> row : rowDatas) {
        Object val = row.get("med_patient_id");
        if (val instanceof String) {
            row.put("med_patient_id", IdCardUtil.mask((String) val));
        }
    }
}
```

## 二、Gradle 工程搭建要点

### 2.1 模块划分原则
```
code/
├── base/                 # 跨业务公共模块
│   ├── {dev}-base-common # 常量/枚举/工具类（零依赖）
│   └── {dev}-base-helper # 数据操作帮助类（依赖苍穹SDK）
├── {cloud}/              # 按业务云分组
│   └── {dev}-{cloud}-{app}  # 具体业务模块
└── {dev}-cosmic-debug    # 调试入口
```

### 2.2 依赖层级
```
common → helper → 业务模块 → debug
    (无苍穹依赖)  (苍穹SDK)  (业务逻辑)  (全部聚合)
```

### 2.3 包命名规范
- 格式: `{developer_flag}.{cloud}.{app}`
- 示例: `med.outpatient.register`
- 插件包: `med.outpatient.register.plugin.{type}` (form/list/operation)

## 三、常见易错点

| 问题 | 原因 | 解决 |
|------|------|------|
| propertyChanged 字段值为 null | model 未加载完成 | 在 afterLoadData 后的事件中处理 |
| 操作插件 dataEntity 字段为空 | 未在 onPreparePropertys 声明 | 必须 add 所有需要的字段 |
| 基础资料联动不生效 | 使用了 setFilter 被覆盖 | 改用 addServiceFilter |
| 查询性能差 | query 全量 + .length 计数 | 改用 queryCount |
| 日期比较异常 | 含时分秒导致不等 | DateUtils.truncate 截断到日 |
