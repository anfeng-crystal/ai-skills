# 表单、列表、布局与控件变更规则

## 精确兼容性

控件合同来自 `control-types.json` 的真实标准实例。每次自动同时匹配：

1. 控件 XML 类型；
2. 宿主 `ModelType`；
3. 所在 `FormMetadata` 的页面 `ModelType`；
4. `ParentId` 指向的语义父容器类型；
5. XML 直接父节点；
6. 属性名、值形态和实际子节点顺序。

基础资料、单据、动态表单、列表、移动端和报表之间不默认兼容；类型名相似或属于同一功能族也不能互换。缺少精确完整实例时补查目标包或同版本依据；未确认部分标为待验证，不能声称现有脚本已通过。

## 修改和移动

- 先锁定真实页面：表单/列表、PC/移动、主/派生布局分别处理；不能拿另一页面的控件证明当前页面。
- `modify` 以有效 `Key/Id/oid` 锚定，只改批准属性。新增属性还必须存在于精确 profile。
- 不给控件补齐通用必录/锁定属性；属性缺省、不支持与显式关闭分别处理，详见 [属性适用性](property-applicability.md)。
- 属性名不能代替值域证据；例如目标版本的 `Lock` 若采用状态列表，就不能写布尔 `true`。从目标 profile、已生效控件或匹配版本 SDK 核验合法序列化值；不把其它布尔属性的写法类推过来。状态也逐项核对，不从可见性或单据状态全集补锁定选项；目标选项没有 `view` 时不自行添加。
- `move` 只改 ParentId，并用新父容器重新查询 profile；禁止自引用和 ParentId 循环。当前候选执行器要求目标父容器能在所选 `FormMetadata` 或其对应标准祖先页面中解析，嵌套的列表、移动页面不参与本页查找；不同页面的重复标识不能覆盖本页节点。未知目标不能因样本 profile 标记为 `unresolved` 而放行。该约束是本地执行器的页面作用域合同，跨页面迁移需要另行核实完整结构合同。
- 复杂区段（下拉菜单、插件集合、规则树）不是标量属性；未有专门结构合同前不通过 `set` 整段拼 JSON/XML。

## 字段和操作绑定

- 列表列默认显示、基础资料 F7 选择列显示和表单控件可见性分别核对。[缺省可见和 F7 可见](https://vip.kingdee.com/knowledge/884604056273646336?productLineId=29&isKnowledge=2&lang=zh-CN)（帮助中心，更新于 2026-09-07，2026-09-26 已读正文）说明前两者属于不同入口；即使该页标注“所有版本通用”，仍不能据中文名称猜 XML 属性、枚举值或插件签名，也不能把默认隐藏视为数据权限隔离。

- `FieldId/ListFieldId/FieldName` 自动解析同业务对象实体字段，按 `binding-matrix.json` 验证“宿主模型 + 字段类型 + 控件类型 + 绑定属性”。字段名存在但类型组合未观察仍阻塞。
- `OperationKey` 不按按钮名称猜。引擎先用表单 `EntityId` 关联同包实体，找不到时才按唯一业务编码关联，再沿实体继承链读取 `Operations` 下的真实操作定义；必须命中“宿主模型 + 操作节点类型 + 表单节点类型”的实际绑定组合。
- `DropdownItem` 的 `OperationKey` 与工具栏按钮同样校验。若操作键不属于实体操作，只允许 `binding-matrix.json` 中同模型、同节点类型、同操作键已经出现的标准表单动作；否则阻塞。
- 结构和操作绑定通过后仍需检查用户权限、界面规则和插件动态控制；静态合同不能证明按钮在当前账号和单据状态下必然可用。
- 可见、锁定、必录和折叠结果同时受界面规则、插件动态赋值、操作状态与权限影响。静态 `Visible` 打开不能单独证明运行时可见。
- 必录字段必须有用户可编辑路径或已验证的自动赋值来源；空值被锁定时不能要求用户补填。隐藏、锁定和必录分别按已确认口径及目标控件能力配置；能力不适用就不写该属性，隐藏不自动等于取消接口必填。
- 弹窗通过点击插件直接回填时，字段标为必录不代表确认按钮会校验。核对按钮的 `CommitValidate` 及实际缺值行为；平台校验足够时不另写一套硬编码字段清单。

## 新增与删除

- 新控件按 [本地新增](local-addition.md) 在已确认页面和父容器中构造，分配新身份、同步字段及操作绑定，并用 `verify-candidate` 检查适用范围。无需先在设计器创建；不得沿用模板的独立身份。
- 删除业务完整节点前检查子控件 ParentId、字段绑定、操作引用和其他包外消费者。
- `action=edit/reset/delete` 是继承差量；恢复继承用 `restore`，不能把父控件复制到业务层或直接删除父定义。

## 输出要求

报告控件中文名和 Key、页面 Key、宿主/页面 ModelType、旧/新父容器、匹配 profile 出现次数、字段/操作绑定结果及动态控制层。只完成静态验证时明确写“未进行真实入口运行验证”。
