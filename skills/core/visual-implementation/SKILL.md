# Visual Implementation

> Cross-platform Agent Skill · 把确认的视觉设计落实到目标媒介。

## 触发条件与交接输入

以用户明确选定的版本、设计参数和之后确认的改动为准。核对源稿、素材、交付格式、目标尺寸和制作范围。收到 UI 设计交接时，对齐同版交互稿、双语设计规范和参数表。仅授权选型时到选型交付为止。已有定稿或明确的局部实现要求时直接制作。需要重新选择设计方向时交给 `design-direction`。

## 实现流程

保留确认稿的构图、主次、图文关系、功能状态和可编辑对象。修改现有作品时，一并保留范围外的内容及业务行为。委派实现时交接同一份稿和验收条件，由负责交付的代理核对成品。

把确认的参数落到项目已有的主题、布局、组件和动效配置。将实际值对应到规范里的参数键、对象和状态，沿用共用值及约定的尺寸覆盖规则。实现阶段有用户确认的调整时，同步对应规范和参数表，供下一轮修改与验收。

- **网页**沿用项目组件、主题和数据流。按目标宽度还原图文关系，核对输入、反馈、键盘和触控行为。需要改动 Web 工程代码时，交给 `frontend-development`，共用同版设计交付与验收依据。[网页实现与验收](references/web.md)
- **原生应用**使用项目已有的平台控件和导航，适配设备尺寸、系统字号和输入方式。[Apple 无障碍设计](https://developer.apple.com/design/human-interface-guidelines/accessibility) · [Android 自适应布局](https://developer.android.com/develop/ui/compose/layouts/adaptive/list-detail)
- **PPT**还原母版、版式和讲述顺序，让约定的文字、图表、图片与分组可独立编辑。[幻灯片实现与验收](references/slides.md)
- **其他媒介**按实际观看方式、交付格式与后续编辑要求选择实现方式。

## 成品对稿

- 用相同内容、状态和目标尺寸并排对照原稿与成品。检查焦点、层级、色彩、裁切、换行和疏密。局部修改同时看相邻内容及受影响的状态。
- 静态作品按实际观看效果验收。有操作、动画或媒体时验证相应行为与结果，并提供可操作的验收入口。交付设计规范或微调说明时，给出可定位的组件、状态、参数键、当前值及单位，用原语和对应的中文含义说明实际效果。需要可编辑源时，在副本中改动代表对象并核对保存结果。
- 页面、替代文字、演讲备注和导出件使用符合各自受众的文案。保留要求的引用和署名，制作说明按用户要求加入。

## 输出与适配失败处理

对稿偏差定位到具体对象，修正后按同一条件复核。格式能力与已确认要求冲突时，说明影响及可行取舍。交付实际成品和约定的可编辑源。完整 UI 成品随附与其对应的双语设计规范和参数表。指出影响使用的未完成项。
