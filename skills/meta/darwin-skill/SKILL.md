# Darwin Skill

> Cross-platform Agent Skill: 用当前证据优化本地可编辑 Skill，不把历史失败直接变成新禁令。

## 范围与能力

- 只读审阅交建议；已授权优化可修改精确目标，不重复确认。bundled/cache/system 默认只给建议，使用受支持配置或可维护源；共享配置、memory 和外部状态遵循任务授权。
- 用户选择逐阶段审核时，保留其阶段间及逐 Skill 检查点；已授权连续优化不另加这些检查点。需要批量循环细节时读 `references/optimization-loop.md`，其审核模式不改变独立发布、付费或 Git 动作的授权要求。
- 第三方安全审查交 `skill-vetter`，安装/分发交本地 `skill-installer`；只改正文不触发安装。
- 先列能力清单：触发和路由、工具/参数、输入输出、授权和隐私、失败恢复、产物与验证。每项明确保留、合并、按需引用、脚本承载或删除理由，不静默丢失。
- 区分硬边界（授权、安全、保密、真实性、用户要求及已验证的数据/平台契约）、默认策略和假设。旧工具路线、阈值和技术推断可被当前源码、SDK 或实验推翻；先核实，不为压缩削弱必要约束。
- 优化后的 Skill 保持跨 Harness 与 Windows/macOS/Linux 可用：通用流程不绑定特定 agent、工具名、安装目录或 shell，宿主差异放在按需适配中；优先复用当前可用能力和经核实的跨平台入口。目标产品的 API、格式和权限合同保持不变，缺少宿主专用工具只阻塞无等价能力的步骤。

## 历史执行审计

用户要求参考历史失败、会话或工具错误时，读 [历史审计](references/history-audit.md)。普通指令优化直接使用当前文件、任务样例和可复现证据。

## 修改与验证

1. 锁定源路径、已有改动和可回滚基线，不覆盖他人资产。
2. 针对改动选择典型、边界和反例 prompt，比较无 Skill、旧版与候选版的触发、动作、授权、恢复和完成条件；验证规模按影响确定。推演标 `dry_run`，真实运行标 `full_test`；不虚报实测或 token 降幅。
3. 小幅文字修订做针对性对比；核心用途、授权或复杂恢复改变时，用可用独立模型/子代理复核。不可用则选择受支持能力或说明限制，不反复调用失败入口。
4. description 只写能力与适用条件，保留能防止实际误路由的边界；工具、参数和流程清单放正文。正文只保留改变触发、动作、门禁、恢复、验证或输出的指令；大块模式细节按需读 references，短入口不强行拆分。中文为主，保留精确命令、字段与状态码。
5. 脚本改动留下触发原缺陷的最小回归检查，优先现有测试。运行相关测试并检查差异；Git 仓库可用 `git diff --check`，无 Git 时检查精确文件差异与空白问题。当前 source tree 具备仓库验证器时，运行 `node <active-root>/scripts/validate-cross-platform.mjs` 和本 Skill 的 `scripts/validate-skill-assets.mjs`；独立迁移或目录结构不适用时，使用当前可用的格式、引用、参数及跨平台检查，不因缺少原仓库脚本阻塞。验证需区分结构检查与各操作系统实测，不能以单系统通过声称三平台通过。纯文本修改不触发无关运行时/生产验证。
6. 逐项复核能力和引用。保留修订须有改善证据且无正确性、权限或调用回退，主观评分上升或字数下降不足以证明效果。失败只回滚本轮目标改动，不动无关资产；已提交的回滚按 Git 授权执行，不用 `reset --hard`。

## 证据与输出

- 本轮交付记录路径、旧问题、处置、能力落点、验证、未验证项和回滚方式。Markdown 为主，HTML/PNG 仅确有阅读收益时生成，不向 Skill 增加过程 README/changelog。
- `test-prompts.json`、`results.tsv` 可选；需要批量评分或留档时读 [评测约定](references/evaluation-contract.md)。无实际 token 时区分静态估算与运行观测；description、正文和按需资源成本分别计算。
- 不把单次路径、命令、决策或模型名变成全局经验。未经要求不提交/分发评测文件；清理只限已授权且本轮可归因的临时产物，保留用户要求的审核证据。
