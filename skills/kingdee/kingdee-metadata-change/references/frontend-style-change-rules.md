# 样式变更规则

## 先确定载体

| 载体 | 执行入口 |
|---|---|
| 元数据控件的宽高、颜色、边距、布局、可见、锁定等属性 | 本 skill，按控件精确 profile 修改 |
| 页面扩展 `index.js/index_m.js`、CSS、运行时 DOM 样式 | `kingdee-frontend-script` |
| 独立 KDApi 自定义控件工程 | `kingdee-custom-control` |

## 元数据样式

- 必须定位实际页面和控件；同名字段在 PC 表单、PC 列表和移动布局可能是不同节点。
- 移动布局同时核对父容器伸缩、滚动、区块间距和长文本宽度；未查看实际效果时，只报告静态校验结果。
- 属性必须在目标节点、祖先有效节点或精确实际 profile 中出现；值形态必须与生产标准观察一致。
- 只新增属性时按 profile 的实际子节点顺序插入，不能整树重排。
- 样式修改不能带出身份、绑定、父容器或其他终端布局变化。
- 继承问题优先恢复或建立正确目标层覆盖，不用 CSS 掩盖错误元数据。

## 表格化布局与多行文本

- 用独立表格标签替代字段标题前，检查原控件是否随标题一起显示必录标识；不能只因实体仍为必录就隐藏唯一可见提示。保留标题或使用目标控件支持且符合当前需求的提示方式，不用静态星号冒充条件必录校验，也不为复选框等类型补造必录属性。
- 调整多行文本高度时，区分外层容器、实际输入区和只读展示区；`max-height` 不能证明固定高度或内部滚动已经生效。按目标控件的实际结构核对自动伸缩、溢出和字数提示占位，使用空值、长文本以及本次涉及的编辑/只读状态检查截断与滚动。仅看离线示意图不能证明真实控件效果。
- 调整表格边框时，先核对容器、标签和输入区各层绘制位置，避免相邻或嵌套边框叠加、断线；修正字数提示裁切时检查可用空间，不把问题直接改成另一种提示位置。尺寸、颜色与选项外观沿用目标页面及已确认设计，不把某次修复的像素值或样式推广为默认。

## JS/CSS

JS/CSS 不属于元数据库模板合同。转交后仍需用真实页面/控件标识、稳定 DOM、PC/移动入口、生命周期和清理规则验证；不能凭截图猜编译类名，也不能让 CSS 承担权限、字段类型、必录、锁定或操作状态语义。
