# 验证合同

## 分层门禁

| 层 | 必测内容 | 允许的完成表述 |
|---|---|---|
| 静态 | 配置、注册 ID、生命周期、功能声明、资源路径、敏感信息、绝对路径、包边界 | source validation passed |
| 单元 | 注册、init/update、页面指令、页面消息、服务端调用、重复销毁 | unit tests passed |
| 构建 | 只从声明的源或已审查外部命令生成 buildDir，拒绝越界和符号链接 | build passed |
| 包 | ZIP 路径安全、根入口、资源齐全、无项目文件、SHA-256 可复算 | package verified |
| 运行 | 目标版本页面加载、网络资源、三条通信链、重复刷新、销毁和回滚 | runtime verified |

前四层不能代替第五层。`release` 只证明本地可复算产物。

## 自动修复

`validate --fix` 仅做确定性修复：

- `platform.schemeId` 与配置 `controlId` 不一致时，以配置为单一真源更新 schemeId。
- `index.js` 恰好有一个字面量 `KDApi.register` 且 ID 不一致时，更新该字面量。

修复后重新跑完整静态校验并报告修改项。缺生命周期、资源、清理、消息合同或业务逻辑时只报错；不能生成猜测实现。

## 运行用例

- 初次加载：入口和资源均成功，根 DOM 只出现一次。
- 后端更新：空值、合法值、重复值和大数据量符合合同。
- 页面指令：已知方法生效，未知方法不产生隐式副作用。
- 控件事件：页面收到约定 `type/payload`；不记录敏感 payload。
- 服务端事件：请求、响应、失败和幂等行为可复算。
- 生命周期：刷新/切页/关闭后监听、定时器和实例全部释放；迟到异步回调不重新挂载。
- 双端：PC 与移动端分别验证，不以响应式推断替代真实目标端。

真实页面动作由 `kingdee-ui-testing` 执行。写操作、上传或生产验证必须进入已批准合同；截图、网络和日志证据脱敏。
