# 批量优化与重复评测

仅在多个 Skill 需要统一比较、或单次修订仍有可复现缺陷时使用。完成条件是已确认的问题得到改善、能力和授权边界保留、所需验证通过；不以评分、压缩比例或循环次数作为交付目标。

## 范围与审核模式

遵循 `SKILL.md` 的源路径、能力保留、回滚和授权规则。用户要求先审方案或逐阶段审核时，保留指定检查点；已授权连续优化时，完成评估、修订和验证，不在每个 Skill 后重复确认。扩范围、独立发布、付费、Git 提交或分发仍需对应授权；只读审阅交付审阅结果。

- 全部 Skills：核对可维护 source tree 与当前宿主实际启用目录；指定 Skills：限定到所选入口及其相关资源。
- 为精确目标保存可回滚基线，保留已有改动。建分支、提交和回滚已提交内容按任务授权执行。
- 有相关历史评测时读取；需要可复核批量结果时按 [评测约定](evaluation-contract.md) 保存 `test-prompts.json`、`results.tsv` 到任务产物目录。未经用户要求不把评测文件加入 Skill 或 Git。

## 选择案例与基线

针对实际改动设计案例，覆盖典型请求、边界或歧义，以及不应触发该 Skill 的反例；小修订只选相关案例。需要保存案例时，每条含 `id`、`prompt`、`expected`、`eval_focus`、`baseline_risk`，格式见评测约定。

对照无 Skill、旧版和候选版，观察触发、结果、权限、调用顺序、恢复和完成条件。保留三组可比较的输入与资源，避免给评估者预设结论。独立评审可用时用于复杂用途、授权或恢复变化；多模型只在需要验证跨模型适用性且宿主可用时选择，不为凑齐矩阵调用未知或失败入口。

- 实际执行任务并产生可检查结果：`full_test`；只推演预期行为：`dry_run`。主代理自评不是独立实测。
- dry_run 仍记录案例、预期结果、无 Skill / 旧版 / 候选版行为及理由；不得把预测差异写成已观测收益。
- 可得时记录模型、input/output/cached/reasoning tokens、首轮成功、重试、人工接管和耗时；说明不可比条件及缺失数据。
- 需要量化比较时，可使用 [评分细则](rubric-detail.md) 与 [评测约定](evaluation-contract.md)；结构评分和效果评分分别说明依据。分数不能抵消能力、正确性或授权回退。

## 修订、验证与停止

按证据确定优先级；一次处理一个能独立验证的问题。可参考 [策略](strategies.md) 选择缩短描述、合并重复约束、按需引用或脚本承载，不为了形式统一重写已可靠的入口。

每轮保留具体问题、处置、能力落点、差异和验证结果。优先沿用可比较案例；只有新修改、失败或未解决疑点才扩大或重复验证。脚本改动运行最小相关回归；纯文本不触发无关运行时或生产验证。

- 有改善证据，且能力、正确性、权限和调用路径无回退：保留。
- 有回退或缺乏支持该修订的依据：只回滚本轮目标差异，保留无关资产并记录原因。
- 必要检查通过、已确认问题解决：交付；仍有具体缺陷才进入下一轮。需要预算上限时可约定最多 3 轮，不要求跑满。
- 连续微调无改善时停止；大范围结构重写若超出原授权，先给出具体范围供确认，授权已覆盖时可按同样的基线与回滚规则执行。不能把瓶颈本身当作删减能力的理由。

用户要求逐阶段审核时，在其指定的案例、基线或单个 Skill 检查点提供差异及证据等待确认；其他独立工作继续。用户要求撤回时，仅恢复本轮修改；不使用 `reset --hard`。

## 交付

按 Skill 汇总修改或保持理由、能力落点、保留/回滚结果、实际测试与 dry_run 数量、未验证项和回滚路径。有量化评测才报告前后评分、观测收益及其口径。可参考 [结果卡](result-card.md)，不强制表格或额外报告层级。
