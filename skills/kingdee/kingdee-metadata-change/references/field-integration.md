# 接口字段、弹窗与分录联动

用于同一业务值跨字段、控件、动态表单、分录和推送报文的修改。复用本任务已有对照表，不为小改动另建大清单。

## 修改前闭合合同

- 每个受影响值核对：接口参数及主/子层级、来源、存储类型、引用对象或映射、可编辑性、显隐、必录、默认值、单位和消费者。核对清单不代表所有字段都要写这些属性；不适用项不配置。接口键必传、非 null、页面必录与布尔必须为 true 分别核对，不能互相替代，详见 [属性适用性](property-applicability.md)。
- 用户手填文本保持手填；未获确认不增加默认映射。基础资料选择存本地引用，发送外部 ID/编码按已确认映射提取；不能根据中文含“单位”或参数含 `Id` 推断类型。
- 是/否交互按确认的布尔控件存储，外部字符串在报文边界转换。保留未勾选 `false` 与空值的区别，不因 `false` 为假值判为缺失。
- 固定值或来源自动字段按用户口径显隐；用户要求隐藏或关闭界面必录时同步弹窗和分录，并保留必要的赋值/发送规则。

## 保持各层一致

- 删除或改名时列出旧/新 Key，检查字段、控件、列表、规则、脚本、插件字段数组、回填和 DTO。已否决的重复名称/编码字段不能仅隐藏，也不能在回填或推送保留旧引用。
- 动态表单字段与分录字段独立核对，类型及业务必录语义一致、各层仅使用自身支持的配置后再检查打开参数、保存返回值、父页回调和再次编辑。不能用动态表单单独预览替代回填验证。
- 在线人工修订先按实际属性合并到本地候选；仍以可信导出物为基线，不直接用旧包覆盖用户刚改的提交校验或业务配置。
- 运行脚本、控件宽高与父容器共同决定布局。修改后从真实父页检查整页；长文本短内容、换行、相邻普通字段和底部按钮都要可见且不重叠，细则交前端与 UI skill。

## 交付顺序

- 字段 Key/类型与 Java 同改时列配套版本、已导入/已部署状态和回滚范围；旧插件仍读取旧 Key 时不能让用户把新元数据当作可用功能验收。部署需已有授权，缺授权只完成可审核产物并准确报告边界。
- 导入失败区分上传、包解析、运行期构建与业务运行。只出现 `null` 时取同次日志的最内层异常及节点，不凭提示猜删更多字段。
- 候选生成、静态检查、逐文件导入成功、入口运行、业务验收分别记录。重新生成候选时保留已验证状态和版本依据，不能把旧验证结果套到新包，也不能把用户已确认通过写回“待验证”。
