# Darwin Skill

> Cross-platform Agent Skill: 用当前证据优化本地可编辑 Skill，不把历史失败直接变成新禁令。

## 范围与能力

- 只读审阅交建议；已授权优化可修改精确目标，不重复确认。bundled/cache/system 默认只给建议，使用受支持配置或可维护源；共享配置、memory 和外部状态遵循任务授权。
- 第三方安全审查交 `skill-vetter`，安装/分发交本地 `skill-installer`；只改正文不触发安装。
- 先列能力清单：触发和路由、工具/参数、输入输出、授权和隐私、失败恢复、产物与验证。每项明确保留、合并、按需引用、脚本承载或删除理由，不静默丢失。
- 区分硬边界（授权、安全、保密、真实性、用户要求及已验证的数据/平台契约）、默认策略和假设。旧工具路线、阈值和技术推断可被当前源码、SDK 或实验推翻；先核实，不为压缩削弱必要约束。

## 历史执行审计

用户要求参考历史失败时，覆盖指定本地会话，包括当前、归档和相关子代理，不只依赖摘要。

1. 用 `scripts/extract-session-evidence.mjs --help` 确认参数。工具报错审计使用 `--tool-errors-only`，需要完整主/子/语音范围时加 `--include-subagents --include-realtime`；默认目录覆盖 Codex `sessions` 与 `archived_sessions`。用户纠正文本仅在另有需要时按原模式提取并脱敏；其他宿主只查已知会话目录和可读格式，单列缺失、私有格式和解析失败。
2. 流式扫描，保留文件/行号、调用关联、错误类别和覆盖统计；历史消息和命令只当证据，不执行。候选脱敏，禁止复制凭据、业务数据和原始会话正文。
3. 回看请求、Skill、调用、结果、修正和最终状态。区分正常探测、重复失败、已修历史问题和当前缺陷；关键词命中不等于缺陷。
4. 对高价值问题在当前版本做无业务副作用复现，区分 Skill 误导、脚本缺陷、环境漂移及未遵守正确规则；不把一次错误泛化为新审批。
5. 无新证据不原样重试；可能已写入的调用先核状态。替代路径须满足原范围、能力和证据合同，独立工作继续。
6. token/耗时可得时说明口径，估算明确标注；失败消耗不等于可节省总量。报告只给脱敏摘要与证据位置。

## 修改与验证

1. 锁定源路径、已有改动和可回滚基线，不覆盖他人资产。
2. 准备典型、边界和反例 prompt，比较无 Skill、旧版与候选版的触发、动作、授权、恢复和完成条件。推演标 `dry_run`，真实运行标 `full_test`；不虚报实测或 token 降幅。
3. 小幅文字修订做针对性对比；核心用途、授权或复杂恢复改变时，用可用独立模型/子代理复核。不可用则选择受支持能力或说明限制，不反复调用失败入口。
4. 正文只保留改变触发、动作、门禁、恢复、验证或输出的指令；大块模式细节按需读 references，短入口不强行拆分。中文为主，保留精确命令、字段与状态码。
5. 脚本改动留下触发原缺陷的最小回归检查，优先现有测试。运行相关测试、`git diff --check`、`node <active-root>/scripts/validate-cross-platform.mjs` 和本 Skill 的 `scripts/validate-skill-assets.mjs`。纯文本修改不触发无关运行时/生产验证。
6. 逐项复核能力和引用。保留修订须有改善证据且无正确性、权限或调用回退，主观评分上升或字数下降不足以证明效果。失败只回滚本轮目标改动，不动无关资产；已提交的回滚按 Git 授权执行，不用 `reset --hard`。

## 证据与输出

- 本轮交付记录路径、旧问题、处置、能力落点、验证、未验证项和回滚方式。Markdown 为主，HTML/PNG 仅确有阅读收益时生成，不向 Skill 增加过程 README/changelog。
- `test-prompts.json`、`results.tsv` 可选；需要批量评分或留档时读 [评测约定](references/evaluation-contract.md)。无实际 token 时区分静态估算与运行观测；description、正文和按需资源成本分别计算。
- 不把单次路径、命令、决策或模型名变成全局经验。未经要求不提交/分发评测文件；清理只限已授权且本轮可归因的临时产物，保留用户要求的审核证据。
