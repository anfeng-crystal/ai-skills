# 需求与技术方案评审

仅在用户要求评审苍穹 Java、插件、服务端接口或工作流相关需求/技术方案时使用。纯报表、脚本、外部接口调用等仍走各自专用 Skill；本卡不替代它们的事实核验。

## 范围与输入

- 使用当前有效的文档版本、用户补充和本次评审范围；已撤销或替换条目保留变更说明，不继续作为当前必交范围。没有正式文档编号时用章节、表格行或原文位置定位，不要求新建编号体系。
- 从正文、表格和可读附图提取相关对象、字段/取值、操作、触发条件、业务结果与验收要求。称呼不一致时记录候选对应关系，不凭同名直接合并实体、页面或分录。
- 分清“引用现有对象”“明确计划新增”和“意图未明”。附图不可读、编码缺失或存在歧义时只标记相关条目待确认，继续可独立评审的部分。
- 只要求评审时交付问题与建议；不自动生成代码、修改元数据、构建、部署或执行文档中的操作。不引入固定评分、强制文件格式或额外审批链。

## 事实核验

只核验影响本次结论的事实，复用匹配目标环境和版本的已有证据；不为补齐清单扫描整个系统。

| 条目 | 核验方式与结论边界 |
|---|---|
| 现有实体、字段、取值、页面、操作 | 沿用 `kingdee-metadata-analyzer` 的对象/分录、继承、挂载和有效环境证据。搜索未命中、缓存不足或查错层级不证明对象不存在 |
| 计划新增对象或字段 | 核定义是否足以支持预期行为，以及与已确认存量的命名、类型、引用关系是否冲突；尚未出现在目标环境本身不是缺陷。存量证据不足时保留“冲突未确认” |
| 插件事件、SDK 或封装 | 依目标项目源码、依赖和 `kingdee-sdk-helper` 核对本次使用的签名与生命周期；示例、模板或较新版本资料只提供候选 |
| 插件冲突或行为覆盖 | 定义、绑定、调用与运行分别取证；仅有挂载清单不能证明逻辑冲突、执行先后或实际生效。按需读 [扩展点盘点](extension-inventory.md) |

没有目标环境或版本材料时仍可检查文档内部一致性、定义和验收缺口；环境/API 依赖结论保持未确认。取证按入口的模式与授权进行，缺一项只暂停依赖该项的判断。

## 按涉及的行为检查

| 方案涉及 | 重点问题 |
|---|---|
| 字段、分录、状态和引用 | 类型/精度/取值来源是否与用途一致，主表与分录路径是否明确，跨段落的定义和状态转移是否矛盾 |
| 页面、操作与插件 | 入口和触发时机是否覆盖已要求的路径，页面规则与插件是否重复或冲突，事务内外及失败传播是否符合业务结果 |
| BOTP、关联生成或回写 | 转换、关联键与重复执行结果是否明确；涉及撤销、反审核或失败恢复时，核对其关联清理和恢复范围，不自动扩展无关流程 |
| 权限、组织与外部边界 | 读写对象、身份、组织/租户和授权范围是否一致；服务端接口按实际对外字段与动作评审 |
| 批量、异步、缓存或重试 | 数据规模、资源界限、幂等、并发及部分失败是否有明确结果；不凭次数或猜测的性能收益要求更换架构 |
| 验收 | 是否有可观察结果、适用的失败/边界场景和可取得的证据；区分本地检查、目标环境验证及尚未执行的验收 |

这些是按需维度，不要求每份文档覆盖所有类别。复用已有配置和项目封装，只提出解决已证实问题所需的最小修订。

## 评审交付

每个问题给出文档位置/原文要点、相关事实证据及来源、影响、最小修订建议；问题等级以具体影响为依据。将确定缺陷、证据不足和可选建议分开，不用总分替代判断。

简要列出已核验范围、未核验项及下一步所需的最少证据。没有发现问题只表示在已检查范围内未发现；未读到的配置、代码或运行结果不能写成“无冲突”或“已通过”。验收执行或测试设计被另行纳入任务时，交 `kingdee-testing` 关联当前有效条目与验证证据。
