# Auth / Session Pattern

## 适用信号
- 页面依赖用户已登录状态
- 请求结果受租户、账号、权限、组织、语言环境或当前浏览器会话影响
- 页面内容公开地址可见，但真正数据只有登录后才出现

## 首选入口
- 先从页面或会话证据核实当前登录态，优先复用已授权且有效的浏览器会话，不要求用户重复确认或重新登录
- 缺少有效登录态时，使用宿主浏览器/电脑操作处理任务授权内的登录步骤；需要用户本人验证时只暂停该步骤并请求接管
- 再用 CDP 做只读补采；不要让脚本替代登录流程

## 最小步骤
1. 根据当前页面或会话证据核实登录是否成功，不把用户再次口头确认作为前提。
2. 优先使用当前宿主已连接且可完成任务的浏览器能力；只有选择本地 CDP 路径时才运行 `check-deps.mjs` 预检。
3. 本地 CDP 路径用 `cdp-proxy.mjs probe` 和 `find-url.mjs` 定位端点/tab；其他宿主使用其文档支持的等价定位能力，不要求安装 CDP。
4. 先读协议元信息、DOM 或快照；页面 JS 按所选工具的参数和副作用合同执行。`--allow-unsafe` 仅是本地 CDP 参数，不是跨宿主通用授权。
5. 输出时只保留必要字段，不回传敏感凭据。

## 证据记录
- 使用了哪个宿主入口
- 是否确认用户已登录
- 读取的是哪个页面 URL / target
- 页面事实、抓取时间和未确认项

## 风险 / 停问
- 未确认登录状态，不继续假设页面可读
- 页面含敏感数据时，先缩小提取范围
- 提交、删除、发消息、付款等写操作按 `../../SKILL.md` 的任务授权规则执行；已有授权覆盖目标、范围和动作时不重复确认，缺少授权或范围变化时先取得相应授权
