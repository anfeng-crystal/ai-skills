# 需求接入基线（首轮 requirement 工单）

## 1. 文档定位
- **适用阶段**：主代理首轮 requirement 接入
- **适用前提**：当前尚无具体业务需求，禁止虚构业务字段、业务流程和行业规则
- **输出目标**：为后续 metadata / frontend / backend / testing 派工提供统一开工门槛与拦截规则
- **当前结论**：本基线已可执行，但**仅允许继续收集业务需求，不允许直接进入开发与测试派工**

## 2. 后续业务需求接入必填信息清单

> 以下信息未收齐前，主代理不得派发具体业务开发工单。

| 类别 | 必填项 | 说明 | 缺失影响 |
|---|---|---|---|
| 需求主信息 | 需求名称、需求来源、业务负责人、优先级、期望上线时间 | 用于确认责任边界与排期优先级 | 无法立项与排工 |
| 业务场景 | 所属行业、场景名称、业务目标、痛点描述 | 必须说明“为什么做、解决什么问题” | 无法判定真实业务价值 |
| 业务对象 | 涉及组织、人员角色、基础资料对象、单据对象 | 明确谁使用、操作什么对象 | 无法拆元数据与权限 |
| 单据范围 | 单据类型（表单/列表/报表/基础资料）、主单据/子单据、上下游单据关系 | 明确交付边界 | 无法划分 metadata/frontend/backend 工作量 |
| 字段范围 | 关键字段清单、字段类型、是否必填、默认值、精度/长度、引用关系 | 字段必须能落到苍穹元数据 | 无法开工 metadata |
| 流程定义 | 流程节点、节点动作、参与角色、驳回路径、终止条件 | 需可映射到工作流/状态机 | 无法开工 metadata/backend/testing |
| 状态流转 | 初始状态、过程状态、完成状态、撤销/反审核状态、状态转换条件 | 必须可执行、可校验 | 无法开工 backend/testing |
| 业务规则 | 校验规则、计算规则、控制规则、异常分支 | 需写明触发条件、处理逻辑、提示语 | 无法开工 frontend/backend |
| 权限范围 | 角色-操作矩阵（查看/新增/修改/删除/提交/审核/反审核） | 必须对应真实岗位 | 无法开工 metadata/frontend |
| 集成边界 | 外部系统、交互方向、同步/异步方式、接口对象、失败兜底 | 无集成也要明确“无” | 无法开工 backend/testing |
| 数据要求 | 初始化数据来源、测试数据口径、历史数据迁移要求 | 至少说明是否涉及迁移 | 无法准备测试与联调 |
| 验收口径 | 业务验收场景、通过标准、失败判定、验收责任人 | 必须可量化 | 无法开工 testing |

## 3. 可选增强信息清单

| 类别 | 可选项 | 价值 |
|---|---|---|
| 原型资料 | 页面原型、字段布局草图、打印样式草图 | 降低前端反复确认成本 |
| 样例数据 | 样单、样表、历史 Excel、接口报文样例 | 提高字段与规则确认效率 |
| 合规要求 | 行业法规、内控条款、审计留痕要求 | 提前识别合规风险 |
| 性能指标 | 并发量、列表数据量、响应时限 | 提前识别技术瓶颈 |
| 权限细分 | 数据级权限、组织级隔离、部门级过滤 | 提前规避返工 |
| 消息通知 | 待办、短信、邮件、企业微信/钉钉触达规则 | 便于 backend/testing 完整验收 |
| 报表需求 | 统计口径、维度、过滤条件、导出模板 | 便于 frontend/metadata 一次到位 |
| 运维约束 | 定时任务窗口、失败重试、监控告警要求 | 便于 backend/ops 联动 |

## 4. 四类工单开工前置条件

### 4.1 metadata 工单前置条件
- 已有通过评审的业务需求文档或按本基线补齐的需求包
- 已明确业务对象、单据类型、字段清单、字段约束
- 已明确流程节点、状态流转、审批/参与角色
- 已明确基础资料引用关系、上下游单据关系
- 已明确哪些内容属于表单、列表、报表、工作流配置

### 4.2 frontend 工单前置条件
- metadata 范围已冻结到可开发粒度
- 已明确页面范围（表单/列表/报表/门户）与交互动作
- 已明确字段联动、按钮可见性、状态展示、校验提示
- 已明确前端权限展示口径
- 如需打印/报表/移动端，已明确对应范围

### 4.3 backend 工单前置条件
- metadata 范围已冻结到可开发粒度
- 已明确状态机、操作动作、业务校验、计算公式、异常分支
- 已明确上下游单据联动或服务接口边界
- 已明确外部集成对象、接口协议、失败处理策略
- 已明确需落插件、服务、定时任务还是消息逻辑

### 4.4 testing 工单前置条件
- 已有需求验收标准最小集
- 已有 metadata / frontend / backend 对应交付物或可部署版本
- 已有测试环境、账号、角色、测试数据准备口径
- 已明确主流程、异常流程、回归范围
- 如涉及集成/消息/缓存，已明确验证点与期望结果

## 5. 缺失信息导致的禁止开工条件

### 5.1 全局禁止开工条件
任一项成立即禁止主代理派发 metadata / frontend / backend / testing：
1. 未明确业务场景与业务目标
2. 未明确业务对象或单据范围
3. 未明确状态流转或流程节点
4. 未明确关键字段清单及字段约束
5. 未明确验收场景与通过标准

### 5.2 分工单禁止开工条件
- **metadata 禁止开工**：缺字段清单、缺单据类型、缺流程节点、缺角色权限映射
- **frontend 禁止开工**：缺页面范围、缺交互规则、缺前端展示状态口径、缺按钮权限口径
- **backend 禁止开工**：缺业务规则、缺状态转换条件、缺接口/联动边界、缺失败兜底
- **testing 禁止开工**：缺验收场景、缺预期结果、缺测试账号/数据、缺可部署版本

## 6. 验收口径最小集

后续任何具体业务需求进入开发前，至少满足以下 8 项：
- [ ] 已明确业务场景、业务目标、需求负责人
- [ ] 已明确业务对象、单据类型、上下游关系
- [ ] 已明确关键字段及字段约束
- [ ] 已明确流程节点、角色、状态流转
- [ ] 已明确校验规则、计算规则、异常分支
- [ ] 已明确权限矩阵与集成边界（无则写明“无”）
- [ ] 已明确可量化验收场景与通过标准
- [ ] 已形成可直接派发到 metadata / frontend / backend / testing 的任务输入

## 8. 首轮需求风险摘要

| 风险项 | 当前状态 | 影响 | 处理要求 |
|---|---|---|---|
| 无具体业务需求输入 | 未解决 | 无法进入真实业务设计 | 先按本基线补齐业务需求包 |
| 无字段级需求 | 未解决 | metadata 无法绘制 | 补齐关键字段与约束 |
| 无流程/状态定义 | 未解决 | backend/testing 无法建立状态机与用例 | 补齐流程节点与状态流转 |
| 无验收场景 | 未解决 | testing 无法开工 | 补齐主流程/异常流程验收口径 |
