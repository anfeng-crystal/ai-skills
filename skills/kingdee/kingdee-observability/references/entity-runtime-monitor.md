# 实体运行监控：选择证据与收束范围

用于字段被谁改写、分录为何增删、提示从哪里抛出或方法耗时/参数异常。先确认目标版本和已有证据：官方说明适用于 V5.0.12+（开发平台搜索“实体运行监控”或 `bos_entitytraceview`）；V6+ 菜单为“系统服务云 / 日志管理 / 实体运行监控”。不根据文章更新时间推断目标环境支持版本。

## 从问题选择方案

| 已确认的问题 | 适合的监听证据 | 缩小范围时要核实 |
| --- | --- | --- |
| 字段值偏离预期 | 字段值改变及其调用来源 | 实体、字段；字段留空表示全部字段 |
| 分录多行或少行 | 分录行增删及其调用来源 | 实体、单据体、增/删；单据体留空覆盖本单全部单据体，行操作留空同时监听增删 |
| 保存、提交等提示来源不明 | 操作提示及实际调用链 | 用已知提示文本列头过滤，再聚焦追溯 |
| 某方法参数或结果可疑 | 方法执行的输入、输出 | 类和方法从实际代码或当前工具定义核实，不凭 Java 名称猜监听标识 |
| 表单请求或插件耗时 | 代码调用耗费或插件性能审计报告 | 记录当前阈值、请求/方法层级及单位；未达阈值可能不输出，缺报告不证明未执行 |

这些是问题相关的备选方案，不要求全部启用。字段变化行及其直系父/子调用链可以定位执行来源，但仍需结合规则、插件、输入和预期业务语义判断是否缺陷。

## 已有证据与新采集

- 本 Skill 负责采集方案和证据解释，不执行监听界面操作。配置/启停监听与业务重现交给能覆盖该动作的已授权执行工具或领域 Skill；本卡不覆盖主入口的客户端、浏览器会话和凭据门禁。
- 只分析已有导出时保持 `offline`；读取现有运行记录仍使用主入口的查询范围。UI 名称不是导出 schema，接入分析脚本前只映射已核实字段，不把实体监控调用链猜成 Trace/span 树。
- 官方工具仅支持当前账号，不能以当前账号没有记录推断其他账号未操作，也不切换账号补采。监听方案按缓存处理，不把它当持久保存方案或全租户审计记录。
- 配置/启用监听会改变采集状态，业务重现还可能新增、保存或审核单据。日志只读授权不包含这两类动作；已有任务授权覆盖时连续执行，否则先交具体采集方案。重现操作交测试 Skill 的相应授权范围。
- 新采集方案明确实体、字段/分录或类方法、当前账号范围、采集时段、停止条件及需要的输出。空条件并非“不监听”；不要把留空样例当默认最小范围。
- 在已授权采集中，“启动”开始抓取；“暂停”只暂停表格刷新，监听仍在进行；完成后用“停止”结束抓取并核实状态，不能以暂停或清空表格作为结束证据。中途失败也报告监听是否已停止，无法核实时明确保留该状态缺口。

## 解释与输出边界

先通过列头过滤定位字段/提示/方法，再用“聚焦追溯”查看相关直系父、子调用。保留方法进入时间和耗时（毫秒），区分参数、调用来源与根因推断。调用堆栈只在部分行显示，且受系统公共参数“显示异常堆栈信息”影响；缺堆栈不能证明没有调用，也不因诊断需要自行修改参数。

报告所用版本、方案、实际范围与采集状态，以及足以支持结论的脱敏片段。方法参数、数据包和导出可能含业务数据，沿用主入口脱敏规则；不为方便分析引出整包或原样复制账号、单据值。未做业务重现或真实平台验证时明确说明。
