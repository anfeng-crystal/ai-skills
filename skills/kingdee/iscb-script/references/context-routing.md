# ISCB 上下文路由与输出契约

## 目录

- 1. 目的
- 2. 上下文决策表
- 3. 信息充分性检查
- 4. 输出契约
- 5. 校验与保存动作矩阵
- 6. 平台层降级模板

## 1. 目的

本文件是 `SKILL.md` 的外部权威参考，用来回答两类问题：

- 当前请求应该按哪种脚本上下文处理
- 校验、运行、保存到底在什么条件下才允许发生

上下文与动作边界以 `SKILL.md` 为准；validator/manifest 只决定本地校验覆盖，不能覆盖目标版本的接口兼容证据，也不能用较新的 bundle 自动提高目标版本。

## 2. 上下文决策表

| 场景 | 典型信号 | 可以使用 | 不能默认假设 | 处理策略 |
|---|---|---|---|---|
| 普通引擎脚本 | “写个脚本”“帮我改脚本”“解释这段脚本” | 用户显式给出的变量名和对象结构 | `src`、`tar`、`param`、`cn`、`$process`、`#request` | 默认路径；优先生成最小必要脚本 |
| 数据映射表达式 | 宏、聚合运算或分录选择器 | `#{...}`、`::`、`[n]`、`[-n]`、`[field=value]` | `return`、分号、脚本变量和平台资源 | 只输出表达式；使用 mapping profile，不送 JAR 编译 |
| 映射内嵌脚本 | 直接赋值或固定比较值中的 `<%script%>` | 目标版本及实际位置确认的集成脚本 | 聚合链与内嵌脚本可互换、未确认的预置变量 | 保留 `<%...%>` 容器；按 `data-mapping-expressions.md` 的版本和工具覆盖边界处理 |
| 数据集成方案 | “来源数据处理脚本”“转换脚本”“目标数据处理脚本” | `src`、`tar`、`$src`、`$tar` | 额外连接别名、更多平台对象结构 | 可使用数据集成上下文；若连接资源信息不足，仍需说明限制 |
| 值转换规则 | “SQL/脚本类型值转换规则” | SQL 型：`#{param}`、已核实的 `use $tar;`；脚本型：`param`、上下文已证实的连接变量 | 默认查询连接、路由和规则类型可互换 | 先选执行连接，再用最小规则类型 |
| 服务流程脚本节点 | “服务流程”“流程脚本节点” | `$process` 和用户给出的资源别名 | 别名固定叫 `cn` | 生成时显式沿用用户给出的别名 |
| 自定义 API / 脚本 API | “自定义 API”“脚本 API” | 用户给出的 API 入参名 | `src` / `tar` 默认存在 | 若参数定义不全，先用参考脚本并标明需替换实际入参名 |
| WebAPI / 开放平台 | “WebAPI”“开放平台调用” | 用户已确认的请求变量；必要时 `#request` | 请求体字段名、响应对象结构 | 若缺结构说明，先给参考脚本并说明待补齐项 |

## 3. 信息充分性检查

先按 `SKILL.md` 从任务声明、现有项目与非敏感版本配置解析目标版本，再用目标依赖/声明或注明目标适用版本的官方资料核对本次所用平台接口。只知道主次版本不证明某个补丁已安装；具体接口已有目标证据时无需另为完整补丁号停问。缺少接口兼容依据时只暂停依赖它的目标代码，保留下面允许的参考说明及独立工作，不重复已有运行或保存授权。

进入平台层上下文前，至少检查以下信息是否充分：

| 场景 | 最低需要的信息 |
|---|---|
| 数据集成方案 | 来源/目标脚本位置，是否允许 `src` / `tar`，是否涉及连接资源 |
| 值转换规则 | SQL/脚本类型、查询源或目标系统、目标实体实际路由、是否跨多个苍穹路由 |
| 服务流程脚本 | 节点类型，流程中可用资源别名 |
| 自定义 API | 实际参数名或最少的参数结构 |
| WebAPI | 可用请求变量、请求体结构或字段名 |

若这些信息不足：

- 允许生成参考脚本
- 必须显式标明“当前缺少哪些资源/上下文”
- 不得宣称“已验证可运行”
- 如提到本地静态校验结论，还必须区分“脚本缺平台上下文”和“本地工具 / manifest 只做弱预检”这两类原因

## 4. 输出契约

| 状态 | 触发条件 | 必须包含的信息 |
|---|---|---|
| `未校验` | 实际未执行校验 | 结果内容本身；明确未执行验证及原因 |
| `已静态校验` | 实际完成静态校验 | 使用了哪种校验；关键 findings；是否通过 |
| `映射静态通过` | mapping profile 专用校验通过 | 表达式、待替换目标证据、未执行平台运行 |
| `平台弱预检` | platform profile 完成官方名称、上下文和安全检查 | 资源依赖、签名证据状态、目标平台待验证项 |
| `已编译校验` | 实际完成不执行业务脚本的编译校验 | 真实 runtime compile 是否通过 |
| `已运行验证` | 已按用户明确要求或既有授权实际完成 runtime 校验 | 实际 `return_value` 或 `runtime_error` 关键内容 |

同一轮回答里，状态必须准确，不要混说。所有本地状态都不自动包含“目标产品版本兼容”；报告目标版本/证据来源及本次接口的兼容性是否已确认，不因本地校验通过就把 8.0 示例用于 7.0 目标。

## 5. 校验与保存动作矩阵

| 用户表达 | 允许动作 | 说明 |
|---|---|---|
| “预览/解释脚本” | 只说明 | 不自动编译、运行或保存 |
| “生成、修改或修复脚本” | 完成必要的本地静态及适用的不执行业务脚本的编译校验 | runtime 校验仍须用户明确要求或已在授权范围内；交付文件按保存契约处理，必要校验可使用本地临时文件 |
| “做静态校验” | 静态校验 | 不能声称真实 runtime 已通过 |
| “做编译校验” | 不执行业务脚本的真实 runtime compile | 不能声称已运行 |
| “做运行验证” | 按授权完成 runtime 校验 | 必须回传实际结果或报错；外部调用继续遵守 run-readonly / run-approved 契约 |
| “修改或修复指定普通现有脚本” | 编辑指定目标并保留任务外改动 | 不重复询问是否覆盖；不适用于 DTS 原包和受控副本的专用门禁 |
| “交付本地文件”或完整生成合同含目标路径及写入授权 | 写入合同指定文件 | 仅给目录时默认 `generated-script.iscb`；新文件遇到名称冲突时，按 SKILL.md 保存契约选择新路径或询问必要覆盖 |

校验 profile：

- engine：生成、修改或修复包含必要静态和适用的 bundled JAR compile；compile 不执行业务脚本。无外部资源 runtime 仍须用户明确要求或已在授权范围内。
- platform：只做 reference-only 弱预检；需要目标平台资源才能确认运行。
- mapping：当前 CLI 只校验映射宏、聚合链和选择器；不覆盖 `<%script%>` 容器。内嵌脚本可单独按实际上下文做适用的 engine/platform 校验，但不能因此声称完整映射已通过；不默认执行 runtime。

## 6. 平台层降级模板

当平台资源不完整时，输出应遵循下面的语义：

- 先给参考脚本
- 再明确指出当前缺少的资源、别名、参数定义或对象结构
- 最后说明“需在苍穹集成平台补齐并验证”
- 若同时提到本地 `check-script` 结果，要额外说明这可能只是工具 / manifest 对平台能力的覆盖边界，不等于脚本语法错误

推荐表达：

```text
以下先给参考脚本。
当前缺少：实际资源别名 / API 参数定义 / 请求对象结构。
需要到苍穹集成平台补齐后再验证。
若 `check-script --mode platform` 只给出弱预检，表示当前仅确认官方名称、上下文和安全边界，不等于平台运行通过。
```
