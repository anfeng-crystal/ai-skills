# 事务管理指南

> 来源: 基于平台API和社区资料整理（https://vip.kingdee.com/knowledge/498888207505798912）
> 日期: 2026-04-12
> 标签: 事务, TXHandle, 操作插件, 大事务, 数据一致性

---

## 摘要
金蝶云苍穹的事务管理围绕操作插件（AbstractOperationServicePlugIn）生命周期展开。平台通过操作服务自动管理事务边界，开发者在操作插件的事务方法内执行数据修改，确保业务数据的一致性和完整性。

## 适用版本
- 金蝶云苍穹 V5.0+

## 核心概念

### 操作插件生命周期与事务边界

```
操作执行流程：
┌─ 非事务阶段 ─────────────────────────────────────┐
│ onPreparePropertys()      → 准备要加载的字段       │
│ onAddValidators()          → 添加校验器             │
│ validate()                 → 执行校验（校验器中）    │
│ beforeExecuteOperationTransaction()  → 事务前       │
├─ 事务阶段 ───────────────────────────────────────┤
│ beginOperationTransaction()          → 事务开始     │
│ executeOperationTransaction()        → 核心处理     │
│ endOperationTransaction()            → 事务即将结束 │
├─ 非事务阶段 ─────────────────────────────────────┤
│ afterExecuteOperationTransaction()   → 事务后       │
└─────────────────────────────────────────────────┘
```

### 事务方法分类

| 方法 | 是否在事务中 | 用途 |
|------|-------------|------|
| `onPreparePropertys` | 否 | 声明需要加载的字段 |
| `onAddValidators` | 否 | 添加校验器 |
| `beforeExecuteOperationTransaction` | 否 | 事务前的准备/校验 |
| `beginOperationTransaction` | **是** | 事务开始，可做初始化 |
| `executeOperationTransaction` | **是** | 核心业务逻辑 |
| `endOperationTransaction` | **是** | 事务即将提交前的最后处理 |
| `afterExecuteOperationTransaction` | 否 | 事务后的非关键操作 |

## 详细内容

### 一、标准事务管理（操作插件）

```java
package com.example.operation;

import kd.bos.entity.operate.result.OperationResult;
import kd.bos.entity.plugin.AbstractOperationServicePlugIn;
import kd.bos.entity.plugin.args.*;
import kd.bos.dataentity.entity.DynamicObject;
import kd.bos.servicehelper.SaveServiceHelper;

/**
 * 操作插件事务管理示例
 * 在保存操作中同步更新关联单据
 */
public class SyncRelatedBillPlugin extends AbstractOperationServicePlugIn {

    @Override
    public void onPreparePropertys(PreparePropertysEventArgs e) {
        super.onPreparePropertys(e);
        // 声明需要的字段，确保在后续方法中能获取到
        e.getFieldKeys().add("id");
        e.getFieldKeys().add("billno");
        e.getFieldKeys().add("amount");
        e.getFieldKeys().add("related_bill");
    }

    @Override
    public void onAddValidators(AddValidatorsEventArgs e) {
        super.onAddValidators(e);
        // 添加自定义校验器
        e.addValidator(new AmountValidator());
    }

    @Override
    public void beforeExecuteOperationTransaction(BeforeOperationArgs e) {
        super.beforeExecuteOperationTransaction(e);
        // 事务外：执行不需要事务保护的校验
        // 如检查外部系统状态、预处理等
    }

    @Override
    public void beginOperationTransaction(BeginOperationTransactionArgs e) {
        super.beginOperationTransaction(e);
        // 事务内：事务开始
    }

    @Override
    public void endOperationTransaction(EndOperationTransactionArgs e) {
        super.endOperationTransaction(e);

        // 事务内：在事务提交前同步更新关联单据
        DynamicObject[] dataEntities = e.getDataEntities();
        for (DynamicObject data : dataEntities) {
            DynamicObject relatedBill = data.getDynamicObject("related_bill");
            if (relatedBill != null) {
                // 在同一事务中更新关联单据
                relatedBill.set("sync_amount", data.getBigDecimal("amount"));
                SaveServiceHelper.save(new DynamicObject[]{relatedBill});
            }
        }
    }

    @Override
    public void afterExecuteOperationTransaction(AfterOperationArgs e) {
        super.afterExecuteOperationTransaction(e);
        // 事务外：发送通知、记录日志等非关键操作
        // 即使这里失败也不影响主事务
    }
}
```

### 二、手动事务控制

在非操作插件场景中需要手动控制事务：

```java
import kd.bos.db.tx.TX;
import kd.bos.db.tx.TXHandle;

/**
 * 手动事务控制示例
 */
public void manualTransaction() {
    // 开启事务
    try (TXHandle h = TX.required()) {
        try {
            // 事务内的操作
            DynamicObject bill1 = BusinessDataServiceHelper.loadSingle(
                id1, "entity1"
            );
            bill1.set("status", "C");
            SaveServiceHelper.save(new DynamicObject[]{bill1});

            DynamicObject bill2 = BusinessDataServiceHelper.loadSingle(
                id2, "entity2"
            );
            bill2.set("amount", newAmount);
            SaveServiceHelper.save(new DynamicObject[]{bill2});

            // 两个操作要么全部成功，要么全部回滚
        } catch (Exception e) {
            h.markRollback();  // 标记回滚
            throw e;
        }
    }
    // try-with-resources 结束时自动提交或回滚
}
```

### 三、事务传播行为

```java
// TX.required() - 如果当前有事务则加入，没有则新建
try (TXHandle h = TX.required()) { ... }

// TX.requiresNew() - 无论当前是否有事务，都新建独立事务
try (TXHandle h = TX.requiresNew()) { ... }

// TX.notSupported() - 挂起当前事务，以非事务方式执行
try (TXHandle h = TX.notSupported()) { ... }
```

### 四、大事务拆分

```java
/**
 * 大数据量处理：分批提交，避免大事务
 */
public void batchProcess(List<DynamicObject> allData) {
    int batchSize = 200;

    for (int i = 0; i < allData.size(); i += batchSize) {
        int end = Math.min(i + batchSize, allData.size());
        List<DynamicObject> batch = allData.subList(i, end);

        // 每批单独事务
        try (TXHandle h = TX.required()) {
            try {
                DynamicObject[] batchArray = batch.toArray(new DynamicObject[0]);
                SaveServiceHelper.save(batchArray);
            } catch (Exception e) {
                h.markRollback();
                logger.error("批次处理失败: " + i + "-" + end, e);
                // 根据业务需求决定是继续还是中断
            }
        }
    }
}
```

### 五、校验器模式

```java
import kd.bos.entity.validate.AbstractValidator;
import kd.bos.entity.ExtendedDataEntity;

/**
 * 自定义校验器
 * 在事务外执行，校验不通过则不进入事务
 */
public class AmountValidator extends AbstractValidator {

    @Override
    public void validate() {
        for (ExtendedDataEntity entity : this.getDataEntities()) {
            BigDecimal amount = (BigDecimal) entity.getValue("amount");

            if (amount == null || amount.compareTo(BigDecimal.ZERO) <= 0) {
                this.addErrorMessage(entity, "金额必须大于0");
            }

            if (amount != null && amount.compareTo(new BigDecimal("999999999")) > 0) {
                this.addErrorMessage(entity, "金额超出允许范围");
            }
        }
    }
}
```

## 注意事项

1. **避免大事务**：大事务执行效率低，可能导致锁等待、阻塞或死锁，应拆分为多个小事务
2. **事务与权限**：需要事务控制或权限控制的业务逻辑必须在操作插件中完成，不能在表单插件中
3. **事务内禁止**：
   - 禁止在事务中调用外部系统接口（可能超时导致长事务）
   - 禁止在事务中做大量计算或IO操作
4. **afterExecuteOperationTransaction 非事务**：此方法在事务外执行，适合发通知、日志等非关键操作
5. **TXHandle 必须关闭**：使用 try-with-resources 确保 TXHandle 正确关闭
6. **标记回滚**：异常时调用 `h.markRollback()` 而非手动回滚
