# 元数据设计指南

> 来源: https://vip.kingdee.com/article/269431412242369280, https://vip.kingdee.com/knowledge/498888207505798912, 基于平台API和社区资料整理
> 日期: 2026-04-12
> 标签: 元数据, 基础资料, 单据设计, 字段类型, 分录, 设计器

---

## 摘要
元数据是金蝶云苍穹平台的核心，通过 XML 格式定义表单结构、实体字段和物理表映射。开发者通过可视化设计器进行拖拉拽配置，无需手写 XML。本文涵盖基础资料、单据、报表、动态表单的元数据设计规范和最佳实践。

## 适用版本
- 金蝶云苍穹 V5.0+

## 核心概念

### 元数据体系结构

| 层次 | 说明 | 存储位置 |
|------|------|----------|
| 设计期元数据 | 设计器保存生成，每个页面各一份 | `t_meta_formdesign`（表单）、`t_meta_entitydesign`（实体） |
| 运行期元数据 | 由设计期解析生成，按类型分多份 | `t_meta_form`（表单）、`t_meta_entity`（实体） |

### 元数据两大组成

| 类型 | 内容 | 说明 |
|------|------|------|
| 表单元数据（form） | 页面控件、布局、样式 | 决定界面长什么样 |
| 实体元数据（entity） | 实体字段、物理表、索引 | 决定数据怎么存 |

### 业务对象类型

| 类型 | 模板 | 适用场景 | 插件基类 |
|------|------|----------|----------|
| 基础资料 | 基础资料模板 | 组织、物料、客户等主数据 | `AbstractBillPlugIn` |
| 单据 | 单据模板 / 单据带组织模板 | 业务流程单据（采购单、销售单） | `AbstractBillPlugIn` |
| 动态表单 | 动态表单模板 | 自定义界面、辅助页面 | `AbstractFormPlugin` |
| 报表 | 报表模板 | 统计分析报表 | `AbstractReportFormPlugin` |
| 树型基础资料 | 树型基础资料模板 | 分类编码、部门树 | `StandardTreeListPlugin` |

## 详细内容

### 一、业务对象编码规范

#### 1.1 编码格式

```
{开发商标识}_{模块}_{业务对象名}[_后缀]
```

| 规则 | 说明 |
|------|------|
| 长度 | 不超过 36 位 |
| 唯一性 | 整个系统中不允许重复 |
| 字符 | 字母、数字、下划线 |
| 前缀 | 必须包含开发商标识 |

**示例**：
- `isv_gl_voucher` — 凭证（isv为开发商标识）
- `isv_pur_order` — 采购订单
- `isv_bas_material` — 物料基础资料

#### 1.2 控件标识规范

- 在当前对象中不允许重复
- 包括：对象唯一标识、单据体标识、字段标识、控件标识
- 字段标识（Key）由字符数字和下划线组成，长度 4-24

### 二、基础资料设计

#### 2.1 基础资料特性

- 基础资料是业务数据的基础引用对象（如组织、物料、员工）
- 支持编码规则自动编码
- 支持启用/禁用状态管理
- 支持数据权限隔离
- 通过缓存机制优化查询性能

#### 2.2 设计要点

```
新建基础资料步骤：
1. 进入【开发平台】→ 对应应用
2. 新建页面 → 选择"基础资料"模板
3. 填写标识（遵循编码规范）和名称
4. 添加字段（编码、名称为必填字段）
5. 配置数据模型（物理表）
6. 保存并发布
```

**标准字段**（基础资料模板自动包含）：

| 字段 | 标识 | 类型 | 说明 |
|------|------|------|------|
| 编码 | `number` | 文本 | 唯一标识，支持编码规则 |
| 名称 | `name` | 多语言文本 | 基础资料名称 |
| 数据状态 | `status` | 文本 | A-新增、B-审核中、C-已审核 |
| 使用状态 | `enable` | 布尔 | 是否启用 |
| 创建人 | `creator` | 用户 | 创建人 |
| 创建时间 | `createtime` | 日期时间 | 创建时间 |
| 修改人 | `modifier` | 用户 | 最后修改人 |
| 修改时间 | `modifytime` | 日期时间 | 最后修改时间 |

#### 2.3 基础资料引用

在单据中引用基础资料字段：

```java
// 获取基础资料引用对象
DynamicObject material = bill.getDynamicObject("material");

// 获取基础资料的编码和名称
String materialNumber = material.getString("number");
String materialName = material.getString("name");

// 设置基础资料引用（正确方式）
MainEntityType et = this.getModel().getDataEntityType();
BasedataProp prop = (BasedataProp) et.getProperty("material");
DynamicObject materialObj = (DynamicObject) prop.getComplexType().createInstance();
// 注意：不能直接用 EntityMetadataCache 创建，类型不一致！
```

### 三、单据设计

#### 3.1 单据模板选择

| 模板 | 适用场景 | 特点 |
|------|----------|------|
| 单据模板 | 不需要组织隔离的单据 | 简单，适合全局单据 |
| 单据带组织模板 | 组织级数据隔离 | 支持组织权限控制 |

#### 3.2 单据标准字段

| 字段 | 标识 | 说明 |
|------|------|------|
| 单据编号 | `billno` | 自动编码，唯一 |
| 单据状态 | `billstatus` | A-暂存、B-已提交、C-已审核、D-已关闭 |
| 审核人 | `auditor` | 审核人 |
| 审核日期 | `auditdate` | 审核日期 |
| 创建组织 | `org` | 单据所属组织（带组织模板） |

#### 3.3 单据体/分录设计

单据可以包含多个分录（单据体），每个分录对应一张物理子表。

```
单据结构示例：
├── 单据头（主表）
│   ├── 单据编号
│   ├── 制单日期
│   └── 组织
├── 明细分录（单据体1）
│   ├── 物料
│   ├── 数量
│   └── 金额
└── 付款分录（单据体2）
    ├── 银行账户
    └── 付款金额
```

分录设计规范：

| 规则 | 说明 |
|------|------|
| 分录标识 | 唯一，如 `entryentity`、`payentity` |
| 序号字段 | 分录自动包含 `seq` 序号字段 |
| 物理表 | 每个分录对应一张独立的物理子表 |
| 主键 | 子表主键为 `fentryid`，通过 `fid` 关联主表 |

#### 3.4 分录操作代码示例

```java
// 获取分录集合
DynamicObjectCollection entries = bill.getDynamicObjectCollection("entryentity");

// 遍历分录
for (DynamicObject entry : entries) {
    String materialNumber = entry.getDynamicObject("material").getString("number");
    BigDecimal qty = entry.getBigDecimal("qty");
    BigDecimal amount = entry.getBigDecimal("amount");
}

// 新增分录行
DynamicObject newEntry = entries.addNew();
newEntry.set("material", materialObj);
newEntry.set("qty", new BigDecimal("10"));
newEntry.set("amount", new BigDecimal("100"));

// 删除分录行
entries.remove(0); // 删除第一行
```

### 四、字段类型设计

#### 4.1 常用字段类型

| 字段类型 | 数据库类型 | 适用场景 | 设计器对应 |
|----------|-----------|----------|-----------|
| 文本 | VARCHAR | 编码、简称 | 文本字段 |
| 多语言文本 | VARCHAR | 名称（需多语言支持） | 多语言文本 |
| 整数 | INT | 数量、计数 | 整数字段 |
| 小数 | DECIMAL | 金额、单价 | 小数字段 |
| 日期 | DATE | 业务日期 | 日期字段 |
| 日期时间 | DATETIME | 创建时间、操作时间 | 日期时间字段 |
| 布尔 | INT(1) | 开关类属性 | 复选框 |
| 基础资料 | BIGINT(FK) | 引用基础资料 | 基础资料字段 |
| 大文本 | NCLOB/TEXT | 备注、长描述 | 大文本字段 |
| 下拉列表 | VARCHAR | 固定枚举值 | 下拉列表 |

#### 4.2 字段设计规范

| 规范 | 说明 |
|------|------|
| 数量金额类 | 必须使用 DECIMAL，不能为空，默认值 0 |
| DECIMAL 精度 | 必须明确指定小数精度（如 DECIMAL(23,10)） |
| 文本长度 | 根据实际存储需求确定，不能一律 255 |
| NOT NULL | 必须设置缺省值 |
| 字段名长度 | 不超过 30 位 |
| 扩展字段前缀 | `fk_{开发商标识}_`（如 `fk_isv_customfield`） |

### 五、物理表设计

#### 5.1 表命名规范

| 对象类型 | 命名规则 | 示例 |
|----------|----------|------|
| 主表 | `tk_{isv}_{系统标识}_{名称}` | `tk_isv_bas_material` |
| 分录表 | 主表名 + entry标识 | `tk_isv_bas_material_entry` |
| 主键索引 | `pk_{isv}_{名称}` | `pk_isv_bas_material` |
| 普通索引 | `idx_{isv}_{表}_{字段}` | `idx_isv_bas_material_number` |
| 唯一索引 | `uk_{isv}_{表}_{字段}` | `uk_isv_bas_material_number` |

#### 5.2 表设计规范

- 所有字段总字节长度不超过 8KB（LOB 除外）
- 必须定义主键
- 必须拥有聚集索引
- 高频查询字段必须建索引
- 设计器中的主键属性必须与表定义主键一致

### 六、扩展与继承

#### 6.1 区别

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| 扩展 | 在现有单据上增加字段/控件 | 标准产品个性化（推荐） |
| 继承 | 创建新单据，继承原单据结构 | 独立新单据基于现有结构 |

#### 6.2 扩展规范

- 源页面字段标识、是否必录、基础资料**不允许修改**
- 源页面字段**不允许删除**或设置"隐藏元素"
- 如不需要显示，使用可见性处理
- 扩展只能垂直扩展，不能水平扩展
- 扩展过一次的应用不可再次扩展，但扩展应用可继续向下扩展

### 七、元数据管理

#### 7.1 重建元数据

当修改设计器后预览不生效时，需要重建元数据：
- 重建过程：重新解析设计期元数据 → 生成运行期元数据 → 清空缓存
- 操作方法参考：[苍穹重建元数据](https://vip.kingdee.com/article/127352988121236992)

#### 7.2 元数据导出/导入

- 通过设计器工具栏的导出功能导出 `.dym` 文件
- 导入时确保标识和 ID 不与现有元数据冲突
- 跨环境迁移推荐使用部署方式而非手动导入

## 注意事项

1. **禁止在生产环境修改元数据**：通过开发环境修改，部署方式推送
2. **禁止直接修改元数据表**：`t_meta_xx` 表由平台维护，不要直接写 SQL
3. **实体元数据是单例**：获取后不能直接修改，应先 Clone 再修改
4. **引用对象类型一致性**：创建引用对象必须通过属性的 `getComplexType().createInstance()` 而非 `EntityMetadataCache`
5. **视图禁用**：业务对象不允许使用视图
6. **运行期元数据类型枚举**：`kd.bos.entity.RuntimeMetaType`
7. **元数据缓存**：运行期元数据有后台缓存，修改后可能需要重建
