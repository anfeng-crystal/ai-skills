# SDK/API 证据来源路由

## 优先级

| 等级 | 来源 | 可确认内容 |
|---|---|---|
| 1 | 目标项目解析后的依赖 JAR、同版本 Javadoc、反射/编译结果 | 当前项目可见类、方法签名和编译兼容性 |
| 2 | 当前 skill 的 SDK 索引及其可核验版本/来源 | 索引中明确存在的类、签名和注释 |
| 3 | 目标项目已编译通过的源码引用 | 该项目版本中的用法；不能自动外推到其他版本 |
| 4 | 金蝶官方产品文档、官方 SDK 文档或官方示例 | 文档明确标注版本范围内的候选/确认信息 |
| 5 | 普通用户发布的金蝶社区文章、项目片段、论坛回答、反编译摘要 | 仅作为检索候选，必须回到 1-4 级复核 |
| 6 | 无来源或第三方转载 | 不用于确认签名 |

同级冲突时以目标项目实际依赖和编译证据为准。源码只存在但未挂载、未编译或未在目标版本出现时，输出“候选”而不是“已确认”。

此表说明来源能证明什么，不授权用高版本来源替代低版本目标。生成代码前按下节判定，不能将“索引可信”解释成“目标兼容”。

编译只能证明签名/类型兼容，不能单独证明权限、事务或运行期效果。官方知识库、SDK 与社区用户帖按发布主体和文档性质分级，不按 `vip.kingdee.com` / `developer.kingdee.com` 域名一刀切；官方正文没有版本时记录 `official-unversioned`，不能因此补出适用所有版本的结论。

## 生成代码的版本判定

1. 复用任务已确认的产品与运行版本，结合项目实际依赖、SDK/声明和配置核对；只有 `7.0` 时保留该粒度，不假定等于最新 7.0 补丁。用户声明 7.0 而依赖显示 8.0 时，报告目标与依赖冲突，先查依赖解析和配置来源；不能用对 8.0 的编译通过冒充 7.0 兼容，也不擅自升级/替换依赖。
2. 对新增或改动的 API 查类全名、完整重载、返回类型和本次依赖的行为。与目标一致的实际 JAR/声明、已确认编译类路径或明确覆盖目标版本的官方文档可作依据；无版本参考卡、不同版本索引和最新示例只能提供候选，不能靠相似名称拼出调用。
3. `confirmed-index` 表示索引记录已查到；版本字符串相同也不检查实际依赖、模块或运行配置。必须另给目标依据，不能把该状态自动转成 `confirmed-project`。官方同版本证据可支持标明版本的示例，但不冒充项目已编译或已运行。
4. 目标为 7.0 时，只有 8.0 记录的 API 不进入可运行实现；先查目标 JAR、同版本文档或已有兼容实现，找到等价方式再写代码。用户明确要求其他版本的独立示例时按其示例目标处理，不改变项目目标；“修改得更新”不等于升级平台。
5. 补丁号未知但目标实际依赖能确认本次 API 时可以继续，不机械阻塞。确有版本敏感能力且已有材料不足时，只暂停依赖它的实现，继续分析、查证和不依赖该能力的修改；需要用户提供缺失事实时一次说明最小缺口，不重复索要已有授权。
6. 验证使用与目标相符的实际类路径/声明。测试桩、手写 mock、静态正则检查或另一版本 SDK 上的编译不能证明目标兼容。按变更做适当编译/类型检查；缺少条件时如实交代，不升级 SDK 来消除编译失败。

## 社区和项目资料

- 记录来源类型、标题/文件、平台版本、发布日期或提交版本；缺一项就标记证据缺口。
- 普通用户发布的社区资料可以提供类名、关键词和场景线索，但不能直接确认方法签名、默认值、事务语义或生产可用性。
- 项目实现属于项目事实，不得写成标品能力；跨项目复用前重新核对依赖和元数据。
- 反编译资料只有在来源、许可证和用途允许时用于定位，不复制实现，不把推断写成官方契约。
- 需要联网核验最新文档时转 `web-access`，只用官方一手技术来源确认；无法访问时保留“未确认”。
- 知识专题的标题/目录和搜索摘要只能定位原文。专题正文需记录具体 `category`、`id` 与 `type` 页面；空壳或登录墙不算读到正文。可使用当前宿主支持的浏览器读取已公开页面，不绑定特定工具名。
- 区分“在此版本没有公开”“标记废弃”“脚本端废弃”“项目内部封装”和“性能选择”。只有同版本 `@Deprecated`/Javadoc 废弃标记或官方迁移公告能支持相应废弃结论，不能靠未命中或批量接口更方便来建黑名单。

## 可核验的官方入口

- [SDK说明](https://vip.kingdee.com/knowledge/specialDetail/218022218066869248?category=218063299277852928&id=636240150510611968&type=Knowledge&productLineId=29&lang=zh-CN) 指向开发者门户；实际进入页面后仍须核对标题、产品和版本。门户页面有具体版本，不以入口名推定当前最新版本。
- [RequestContext：Cosmic V8.0.1](https://dev.kingdee.com/sdk/Cosmic%20V8.0.1/javadoc/kd/bos/context/RequestContext.html) 可确认该版公开 `public long getCurrUserId()`；该页未列 `getUserId()`，不能据此推断后者在哪个旧版本废弃。
- [OperationServiceHelper 官方知识](https://vip.kingdee.com/knowledge/specialDetail/218022218066869248?category=255694431574577408&id=255644921388790272&type=Knowledge&productLineId=29&lang=zh-CN) 同时列出 `Object[] ids` 和 `DynamicObject[] dataEntities` 的四参数入口。不能把存在替代重载解释成旧参数形态必然无效；精确版本继续回到目标 SDK。

## 输出状态

- `confirmed-project`：与目标版本一致的项目实际依赖/声明或编译已确认；仅代表已核实的签名/类型范围。
- `confirmed-index`：当前 SDK 索引已确认，但目标项目版本尚未确认。
- `official-versioned`：官方、带版本资料确认。
- `official-unversioned`：已读取官方正文，但没有可确认的目标版本范围。
- `candidate-community`：社区或项目片段只提供候选。
- `unconfirmed`：证据不足或来源冲突。

输出类全名、完整签名、证据状态、来源版本、目标版本和目标依据；未验证的编译/运行分开标记。不要把多个来源拼成一个不存在的签名，也不要隐藏来源与目标的版本差异。
