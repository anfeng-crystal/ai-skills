# 大任务提醒点击插件（AbstractTaskClick）

## 适用范围

`AbstractTaskClick` / `TaskClick` 处理前端后台任务提醒条目的点击、子按钮和清除。后台执行逻辑属于 `AbstractTask.execute`，见[后台任务模板](../../../templates/task-plugin-template.md)。任务标识 `taskId` 不自带采购、报销等业务步骤含义，`JobFormInfo` 是任务目标和进度界面参数。

官方[后台任务提醒](https://vip.kingdee.com/knowledge/669939940880079104)说明状态反馈与清除行为；[大任务异步框架](https://vip.kingdee.com/knowledge/323506428528578560)说明后台执行和发起界面的分工。两篇中的 Java 代码应按目标脚本声明转换，不能直接视为 KingScript 导出合同。

## 导入和事件合同

下列入口与已核验的 7.0 脚本声明一致，其他目标补丁仍按实际声明确认。

| 类型 / 方法 | 归属或合同 |
|---|---|
| `AbstractTaskClick`、`TaskClick`、`JobFormInfo` | `@cosmic/bos-core/kd/bos/schedule/form` |
| `ClickEventArgs`、`ItemClickEventArgs` | `@cosmic/bos-core/kd/bos/schedule/form/event`，不是普通控件事件包 |
| `setContext(mainView: IFormView, jobFormInfo: JobFormInfo, taskId: string): void` | 接收上下文；重写时将参数交给 `super.setContext` |
| `click(e: ClickEventArgs): void` | 点击任务条目；`e.setClearTask(boolean)` 控制是否清除提醒 |
| `itemClick(e: ItemClickEventArgs): void` | 点击条目子按钮；由 `e.getItemKey()` 读取实际按钮标识 |
| `release(): boolean` | 任务结束后用户清除条目时，true 同意清除，false 暂时保留 |

`release` 不是页面关闭或切换事件；返回 false 也不表示平台必然记录“资源释放失败”日志。不要把它当作缓存和临时资源一定会执行的清理出口。

## 最小点击处理示例

示例只演示状态检查、提示及条目清除。任务结束包含失败、终止等状态，不等同于业务成功；未结束时只提示，不自动重开进度界面。

```typescript
import { AbstractTaskClick, JobFormInfo } from "@cosmic/bos-core/kd/bos/schedule/form";
import { ClickEventArgs, ItemClickEventArgs } from "@cosmic/bos-core/kd/bos/schedule/form/event";
import { IFormView } from "@cosmic/bos-core/kd/bos/form";

/** 前端后台任务提醒条目的点击处理；不启动、停止或写入真实任务。 */
class TaskReminderClickPlugin extends AbstractTaskClick {
  /** 处理点击前接收平台上下文，不把任务标识解释为业务流程步骤。 */
  setContext(mainView: IFormView, jobFormInfo: JobFormInfo, taskId: string): void {
    super.setContext(mainView, jobFormInfo, taskId);
  }

  /** 点击条目文字区；结束后清除提醒，运行中保留提醒并提示状态。 */
  click(e: ClickEventArgs): void {
    e.setClearTask(false);
    const mainView = this.getMainView();
    const taskInfo = this.queryTask();
    if (taskInfo == null) {
      mainView.showTipNotification("未取得任务状态，请稍后重试");
      return;
    }
    if (taskInfo.isTaskEnd()) {
      mainView.showTipNotification("任务已结束");
      e.setClearTask(true);
      return;
    }
    const parentView = this.getParentView();
    if (parentView == null) {
      mainView.showTipNotification("任务尚未结束，发起任务的页面已关闭");
      return;
    }
    parentView.showTipNotification("任务尚未结束");
  }

  /** 子按钮标识由实际界面约定；这里只展示标识，不假定内置按钮动作。 */
  itemClick(e: ItemClickEventArgs): void {
    this.getMainView().showTipNotification("子按钮：" + e.getItemKey());
  }

  /** 任务完成后用户清除条目时允许关闭；false 表示暂时保留进度条。 */
  release(): boolean {
    return true;
  }
}
let plugin = new TaskReminderClickPlugin();
export { plugin };
```

## 注册、进度与消息边界

- `getMainView()` 获取首页；`getParentView()` 获取发起页面，页面已关闭时可能返回 null。
- `queryTask()` 查询任务状态；结果和 `TaskInfo.isTaskEnd()` 应分别判断，业务结果还需按任务返回合同解析。
- `getJobFormInfo()`、`getTaskId()` 提供任务上下文，不提供业务步骤映射或执行入口。
- 官方 Java 例用 `JobFormInfo.setClickClassName` 绑定点击实现；KingScript 模块/单例如何注册须核目标平台，不能把 Java 类名或字符串 `plugin` 猜作注册值。
- 已核验的 `AbstractTaskClick` 脚本声明不包含 `execute` 或 `showProgressForm`。Java 示例里的重开进度页逻辑须有目标脚本可见接口或项目 wrapper；不要通过 `any` 绕过缺口。
- 子按钮的停止、撤销或结果查看行为必须按实际按钮和服务合同实现，`getItemKey()` 本身不会执行这些动作。

## 业务场景实施要求

以下保留业务目标与查询口径，需由项目已确认的页面、权限和任务参数合同实现；它们不是内置流程，也不是已完成的可运行实现。界面跳转如使用 `BillShowParameter`、`ListShowParameter`，分别从 `bill`、`list` 包导入；单据新增状态用目标声明支持的 `OperationStatus.ADDNEW`，不要传字符串 `"addnew"`。

| 场景 | 应保留的业务要求与原选择条件 | 边界 |
|---|---|---|
| 采购 | 选择供应商 → 创建采购订单 → 确认入库 → 生成应付单；各动作打开相应列表/新增页面，按业务上下文携带参数；子按钮提供采购流程帮助提示（原 `viewhelp`）；原候选实体为 `bd_supplier`、`pm_purorderbill`、`im_instock`、`ap_paybill` | entity/form/list 标识、上下文参数以及步骤映射须来自目标项目，不由调度 taskId 推定 |
| 费用报销 | 差旅费报销新增、日常费用报销新增、查看当前用户审批中报销单数量（`creator=当前用户` 且 `billstatus=B`，`count(id) as cnt`）；子按钮查看报销历史和制度说明 | 不把当前用户的审批中报销单描述为当前用户待办；状态值和字段标识要核目标元数据 |
| 合同 | 初始化中针对合同审批动作预检当前用户角色，原条件为 `bos_user_role.user=当前用户` 且 `role.number=contract_approver`；保留新建合同、待审批列表，以及按合同类型加载配置的业务要求 | 提示无权限不等于阻止操作；真实审批权限仍须权限服务/操作合同，初始化预检不替代点击与服务端检查 |
| 生产制造 | 创建工单；领料前要求存在已审核、未关闭工单（`billstatus=C` 且 `closestatus!=B`）；工序汇报前要求已审核且类型为 production 的领料记录（`billstatus=C` 且 `billtype=production`）；产品入库前要求已审核工序汇报（`billstatus=C`） | 原查询没有限定同一工单/组织/批次，不能把“任意存在”升级成当前步骤的前置条件已经满足；落地时需业务关联合同 |
| 客户 | 点击条目查看客户列表；子按钮新建客户、查看列表、导入客户、查看信用额度；信用查询保留 `org=当前组织` 且 `enable=1`，汇总 `creditamount` 和 `usedamount`，可用额为总额减已用、两位小数 HALF_UP | 空汇总、BigDecimal 导入、实际金额类型及列表/引入表单都要核实，不用伪完整片段承担这些未证合同 |
| 项目 | 当前负责人项目进度统计（`manager=当前用户` 且 `closestatus!=B`）；总数 `count(id)`，完成数为 `status=C` 的计数；支持新增项目、查看缓存统计与项目列表；保留临时缓存清理意图 | 原用户级缓存键不能证明任务隔离；`release` 不是面板关闭事件，缓存有效期和清理时机须另有合同。原 `AppCache` 调用未在本轮验证 |


业务元数据、注册、任务执行、消息、数据库和缓存行为，以目标项目的实际合同为准。
