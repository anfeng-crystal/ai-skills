# 扩展点盘点与治理

用于模块扩展点清单、绑定审计、升级影响或治理优先级分析。只查一个标准扩展点时，沿用 [业务拓展点查询](../rules/decision-matrix.md#business-extpoints)；字段与挂载事实交 `kingdee-metadata-analyzer`，签名交 `kingdee-sdk-helper`。本流程不授权注册、启停、删除插件或迁移接口。

## 范围与发现

先固定产品版本、模块、代码版本，以及是否包含目标环境绑定。只有源码时可交源码盘点，并明确未覆盖线上状态；不为补齐表格自动联网。

按模块实际形态收集候选，不以一种扫描模式代替全部来源：

| 来源 | 要关联的证据 | 不能直接下的结论 |
|---|---|---|
| 业务扩展接口与触发代码 | 场景编码、接口、调用位置、参数、默认实现及前后/替换调用顺序 | 类名像插件或出现 `PluginProxy` 就是可用扩展点 |
| 元数据差量与派生页面 | 母体、派生对象、布局/操作、最终插件列表、启用状态和顺序 | Java 扫描零命中即没有扩展；某层 `remove` 即所有入口失效 |
| 基类/模板方法继承 | 实际继承链、调用方、方法可见性、目标版本声明 | 每个 `protected` 方法都允许公开扩展 |
| 反射或自定义分发器 | 配置来源、目标类/方法、真实调用链、公开扩展依据 | `Invoker`、`forName` 或 `invoke` 命中即可视为受支持的扩展合同 |

使用项目源码、依赖和现有查询产物交叉消歧。按“环境/代码版本 + 场景或宿主对象 + 事件/操作 + 实现”关联，不能只按简单类名合并不同绑定。弃用判断保留原标记及版本，不把业务自定义标记、SDK 弃用与扫描不到混为一谈。

## 证据状态与台账

分别记录以下维度，允许部分未知，不用一个“已确认”掩盖缺失层：

- **定义**：接口/方法和目标版本声明是否已确认。
- **调用**：触发位置、条件、前后/替换语义、异常和事务边界是否已确认；方法名不是事务证据。
- **绑定**：目标环境有效元数据中的对象、操作、插件、启用状态及顺序是否已确认。
- **运行**：部署构件与实际调用证据是否已取得；有绑定不等于已运行。

最小台账列为：业务动作、场景/宿主对象、事件/操作、接口与实现、发现来源、代码位置、目标版本、绑定状态、运行证据、缺口与建议。仅在用户需要时扩为表格文件或增加负责人、迁移批次等字段。

“未绑定”“未启用”“未找到调用”和“尚未查询”分别报告。无法确认有效消费者时列待核实，不能命名为僵尸后直接删除；源码中存在也不自动纳入迁移范围。由有效消费者、调用方契约和本次目标共同确定变更范围。

## 优先级与后续动作

用户要求 Top-N 或治理顺序时，先说明排序目标是业务收益、故障风险还是升级成本，再用已取得的影响范围、发生频率、绕过入口、兼容风险和改动成本说明理由。缺失数据标未知，不自行填分数或把固定权重当平台标准。有效候选不足 N 时如实交付，不用猜测补齐。

迁移建议须关联现有调用方、替代合同、挂载变化、回归路径和恢复方式。只有已获准实施的部分进入代码或元数据修改；已有授权齐备时直接执行，不因本台账追加审批。

验收时区分源码扫描、元数据核对、目标编译和实际调用。输出覆盖范围及未覆盖来源，不能把只读盘点写成部署、兼容性或业务运行通过。
