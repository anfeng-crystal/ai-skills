# 实体与字段变更规则

删除子树引用与继承字段的复核依据见[云端知识](https://chatgpt.com/space/page_39a9515828b88191a49edd3efba88b2a)；关键变更门禁继续按本文执行。

## 自动定位

字段必须在目标 `EntityMetadata` 中按唯一 `Key/Id/oid` 定位。继承差量的 `oid` 由实际实体祖先链还原；字段类型、XML 父节点、属性和值形态来自 `entity-types.json`，不按名称猜标签。

页面上的标题、顺序、宽度、显隐和锁定不是实体字段属性，转到实际 `FormMetadata` 控件。一个需求同时新增字段和列表列时，合同包含两个独立节点，执行器自动验证绑定关系。

## 修改已有字段

- `modify` 只改已存在标量属性；字段 `Id/PkId/Key/MasterId/ParentId` 不变。
- 新属性先核对精确“字段节点类型 + ModelType + XML 父节点”的适用性；样本出现不等于本次应配置，规则见 [属性适用性](property-applicability.md)。目标类型不支持必录时不添加 `MustInput`，也不从接口必填推导实体必录。
- 布尔、数值、颜色和尺寸遵守实际值形态；复杂子树不能通过 scalar set 拼装。
- 类型、引用对象、集合/分录归属、物理列或默认值语义变化前，调用 `kingdee-metadata-analyzer` 盘点表单、列表、移动布局、报表、插件和数据消费者。

## 新增字段

默认按 [本地新增](local-addition.md) 构造字段及新身份；本地候选用 `verify-candidate` 检查，平台导出候选可用 `verify-platform-candidate`：

- 基线不存在、候选恰有一个完整字段节点；
- 节点类型、模型和父节点有标准完整实例；
- 精确身份合同的共有身份属性齐全；
- 若同时新增控件，控件绑定值解析到该字段，字段类型—控件类型组合已观察；
- 移除批准新增节点后无其他结构差异。

不要求先在平台创建字段或证明平台内部身份算法。基于实际格式生成的新身份仍须检查冲突、引用，并在已授权目标环境导入验证。

## 删除、移动和存储

- 删除前检查整个待删 XML 子树的身份与剩余节点引用；执行器覆盖包内标量引用及已观察的规则 `Fields/FieldId/Id`，随子树一起删除的内部引用不阻断。表达式、其它复合引用及包外消费者继续由 analyzer 取证，不能把扫描通过当作引用全集已清空。
- 继承字段差量用 `restore`，不删除或复制父字段。
- 改分录/父实体必须用 `move`，新父节点可解析且不成环；涉及存储或物理 DDL 时另交 `kingdee-sql-and-data`。
- `mainentityinfo` 只验证主实体映射和能力，不代替普通字段定义与物理列证据。
