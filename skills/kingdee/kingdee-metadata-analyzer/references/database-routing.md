# 业务库定位

此流程只取路由和连接证据。查业务值再补所需字段映射，不触发全量元数据分析。

## 只读入口

```text
<python> <skill-root>/scripts/bootstrap-python-env.py -- <skill-root>/scripts/resolve-business-db.py --config <环境配置> --environment prod <entity1> <entity2>
```

指定数据中心时加 `--datacenter-id <ID>`；已有登录配置不在默认命名位置时加 `--login-config <路径>`；已知管理中心库时加 `--management-db <库名>`。超时默认 10 秒，可用 `--timeout` 调整。

入口复用元数据密码解析，依次完成：

1. 从任务或同环境登录配置取得数据中心；与管理中心的元数据库映射核对。
2. 只读目标实体设计，解析主表和有效 `dbRoute`，仅在缺项时读取祖先。
3. 在管理中心 `t_mc_dbsource` 中按数据中心读取路由，解析单值、逗号列表或 JSON 数组，完整项匹配 `fdbid`。
4. 以 `fdbinstance` 切换现有环境连接的数据库；按精确表名核对实际 schema、列数并执行 `SELECT 1 … LIMIT 1`。同库实体共用一次连接。

输出每个实体的路由、数据库、schema、主表及验证结果，不读取业务字段值、不保存配置或业务样本。重复使用本次结果，不为每张表重新发现管理中心或全量采集。

## 管理中心字段

| 字段 | 含义 |
|---|---|
| `t_mc_dbsource.fdatacenterid` | 数据中心，须与任务/同环境配置匹配 |
| `fdbid` | 一个或多个逻辑路由，不能仅用单值等号或子串匹配 |
| `fdbinstance` | 物理数据库名 |
| `fdbschema` | 可选 schema；先去空白，NULL、空串和纯空白均按未指定处理 |
| `fdbsource` → `t_mc_dbconnection.fid` | 登记连接，`fip/fport` 仅在连接诊断需要时读取；两侧类型不同时显式转换 |

`fdbschema` 未指定时，以目标连接和实际表所在 schema 为准，不报告配置冲突。非空值与实际位置不符时才记录差异。登记地址与现有入口不同，不阻断现有入口上的对应库核查。

## 适配与失败

- 入口适用 PostgreSQL 和上述管理中心结构；缺表/列、特殊实体或多分片时按实际结构窄查。先查 `information_schema`，不猜表和列，不取第一候选。
- 数据中心不明确：先补同环境配置来源；已有路由都指向共同目标时可继续只读核查，但不宣称已选定唯一数据中心。
- 多个实际目标或 schema：用路由/项目配置消歧。空结果先核编号、状态和派生实体；只有瞬时网络错误有限重试。
- 关联实体按实际 `BaseEntityId/BillEntityId` 独立定位，分录按自身物理映射核对。跨库按限定 ID 分步查询，不用同名复制表代替权威关联表。
- 数据库工具未注册时可用本入口；现有数据库路径确实不可用再用已授权 API，需要页面证据时才用浏览器。
