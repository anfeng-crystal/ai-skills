# 组件耗时与证据回指

仅在目标日志出现 BuildTree、RPC 或缓存指标时使用。本卡是阅读与解释合同，不新增 `analyze_logs.py` 的解析字段，也不假定某版本必有某种日志格式。

## 先确认来源与口径

- 保留原始输入；每个提取值或派生结论关联文件及行号、JSON 路径或原始记录定位。对外使用脱敏副本、局部记录别名和不含敏感值的位置，不复制凭据、业务参数或内部 URL。
- 从实际样本及目标导出说明/源码确认字段、单位和统计含义：单次/累计、请求/服务/实例、采集时间窗、采样或截断条件。样例中的字段名和阈值不能直接成为目标合同。
- 区分 trace、span、实例、业务维度及调用方向。用于对比的身份和维度须在授权材料内核对，报告用一致的脱敏别名；只有时间相近不能证明同一请求或同一调用。
- 缺失、未采集、被截断和数值零分别保留；未知单位不擅自当毫秒。经确认的单位换算、字段映射及过滤条件随证据记录，不修改原文件。

## 按组件取证

| 组件 | 需要区分的证据 | 结论限制 |
|---|---|---|
| BuildTree | 构建总耗时、查询阶段、压缩阶段与输入/输出大小；各字段是否确实属于同一次构建 | 总耗时与分阶段耗时可能包含或重叠；字节数不是时长。判断重复构建须先确认同请求、同维度及重复发生位置，跨 trace/维度的相似记录不能合并 |
| RPC | 客户端等待、服务端执行、排队，以及能相互关联的调用标识和起止时间 | 调用方向、时钟或采样范围不齐时分别报告；客户端耗时减服务端耗时不能直接命名为网络耗时，父 RPC 可能已包含子 DB/RPC |
| 缓存 | 调用次数、累计耗时、单次分布和统计范围；同请求内重复访问的对象/维度 | 平均值不能证明每次调用慢；多次访问不自动证明缓存失效、击穿或 N+1。只有汇总而无单次样本时不推造分布或根因 |

## 汇总与 Trace 的关系

1. 比较前核对目标、时间窗、实例、请求范围、维度、单位及采样覆盖；日志汇总与 span 可能来自不同收集器或统计层级。
2. 保留各来源的值和定位。出现次数/耗时差异时记录差异与缺口，不用最大值、最后一条记录或较大样本数自动裁决“真实值”。
3. 请求墙钟耗时、各调用累计耗时及独占耗时分别报告。未证实父子包含、并行重叠和完整覆盖前，不累加 span 当总耗时，不从总耗时减若干阶段推导“其他耗时”。
4. 真实独占耗时需要可比的起止区间和完整层级。已有可比区间但采集不完整时，仍可计算“已观测区间并集”和“未被已观测 span 覆盖的区间”，说明去重、重叠处理及样本范围；后者不能命名为真实独占、其他或网络耗时。不能靠单个 duration 推出缺失区间。

## 结果与下一步

给出证据定位、原值/单位、换算或聚合条件、结论及置信度；无原始记录或口径未确认时，只能报告转述值和待证假设。不能把解释清单写成“脚本已检测”或平台已验证。

映射到 `durationMs` 等受支持字段不保证进入 analyzer 的分类输出；未输出的组件指标保留在脱敏人工证据表中，记录映射及原始定位，不能把分类结果为空当作组件无耗时。

只建议能区分当前假设的最小补证，例如同请求的关联 span 或同维度构建记录。查询继续受当前 offline/query 范围约束；新增监听、改采样配置、业务重现或扩大窗口不由诊断建议自动授权。
