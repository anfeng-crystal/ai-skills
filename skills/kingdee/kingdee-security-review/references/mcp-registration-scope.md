# MCP 注册对象、租户范围与生效证据

用于已授权的 MCP 服务范围审阅、注册状态诊断或迁移计划检查。先确认目标版本与服务类型；以下租户自建/账套级规则来自 V9.0.0。离线导出用 `audit`，读取已知目标现状用原 `audit-readonly` 合同；本卡不执行发布、下架、状态重置、导入或权限变更。

## 对象与暴露范围

| 检查对象 | V9 产品合同 | 审阅应保留的证据 |
| --- | --- | --- |
| MCP 与 API | 一对一；支持 API服务/RESTful API 引擎 | 实际关联 API、引擎、开发商标识与服务记录；名称相似不是关联证明 |
| 系统内置 | 金蝶标准开发商发布标准 API，面向全体租户提供 | 服务来源与标准 API 归属；可见不等于调用用户已获业务权限 |
| 租户自建 | 只能关联本租户二开 API，可见范围为当前账套 | 租户、账套与开发商归属；不能只检查开发商标识非 `kingdee` 就认定可导入 |
| 租户维护/导入 | 只能维护自建服务，不能修改内置服务或借 YAML/DTS 导入标准内置服务 | 候选包和目标的服务来源/归属，不把导入文件当权限绕行方式 |
| DTS 跨环境迁移 | 不支持跨开发商标识同步 | 源与目标标识及服务关联；“跨环境”不代表可跨开发商或跨租户暴露 |

把工具发现、第三方应用 API 授权、业务用户操作权限分层审阅，后两者沿用 [OpenAPI 审计](openapi-audit.md)。客户端 Token/账套及 `inputSchema` 来源问题按需读 [MCP 发现参考](../../kingdee-openapi-client/references/mcp-discovery.md)，不复制或推测鉴权协议。

## 注册状态与验证

- 原样记录当前状态及异常信息：`待注册`、`已发布`、`待更新`、`下架中`、`已下架`、`失败`。界面状态、网关发现结果和实际业务执行结果各自证明不同环节；未实际调用就不声称业务成功。
- 默认扫描间隔约 5 分钟是诊断线索。API 信息变更可使服务进入“待更新”，等待扫描重新注册；仅到达时间或看到待更新不能证明新定义已经生效。核对后续状态和网关实际返回的工具定义，避免重复触发变更。
- 修改 **MCP 服务记录本身** 时，已发布/待更新需先下架；这与关联 API 变更后的自动更新是不同路径。下架、重置注册状态会改变服务可用性或触发发布，不属于只读诊断。
- “失败”先读该服务异常日志，再核对关联 API 是否存在/状态是否正常以及 MCP 服务运行证据。默认扫描已过仍待注册，继续收集部署、节点/服务和日志证据；不以重置状态代替查因，不循环重试。
- V9+ Monitor 关键词用 `McpAccountTool`；旧集群级 MCP 用 `OpenApiMcpProvider`。旧集群级可能只扫描一个数据中心，其他中心状态不变；仅在确认版本、扫描目标及内置服务数据一致时解释这个差异，不能把它套到 V9 账套级隔离。
- 标品更新的预置脚本 `UNPUBLISH`（待注册）与 `SUCCESS`（已发布）影响是否重新扫描，先核对实际脚本和版本。文档的状态重置/脚本建议是候选变更，不在审阅中改脚本、发布或下架。

报告具体不一致、来源版本与目标证据，区分产品设计、目标偏差和待验证风险。缺少可见工具或导入被拒本身不是越权漏洞；未知权限链路仍按主入口证据等级处理。注册状态恢复方案需说明影响工具、预期不可用时段和如何核验生效，实际变更仍需任务授权覆盖。
