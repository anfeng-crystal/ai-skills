# ISCB Script Quickstart

## 1. 默认行为

这个 skill 默认会：

- 生成、解释或重构 ISCB 脚本
- 优先沿用你给出的变量名、列表和对象结构
- 在未说明上下文时，按普通引擎脚本处理
- 输出干净、简洁、最小必要的脚本

这个 skill 默认不会：

- 自动编译
- 自动运行
- 自动保存到本地
- 默认假设 `src`、`tar`、`param`、`cn`、`$process`、`#request`

如果你要求的是平台层脚本，但没有提供资源别名、API 参数定义或对象结构，它只会先给你参考脚本，并明确说明还需要到苍穹集成平台补齐资源后再验证。

## 2. 最常用的请求方式

### 只生成脚本

```text
帮我生成一个 ISCB 脚本，循环 inputList，把字段投影成新的列表。
```

### 生成并做静态校验

```text
帮我生成一个 ISCB 脚本，并做静态校验。
```

### 生成并做编译校验

```text
帮我生成一个 ISCB 脚本，并做编译校验。
```

### 生成并做运行验证

```text
帮我生成一个 ISCB 脚本，并做运行验证。
```

### 生成并保存到本地文件

```text
帮我生成一个 ISCB 脚本，并保存到 /path/to/scripts/order-mask.iscb
```

### 只给目录，让它自动命名

```text
帮我生成一个 ISCB 脚本，并保存到 /path/to/scripts/
```

如果你只给目录、不指定文件名，默认文件名是：

```text
generated-script.iscb
```

### 解释已有脚本

```text
帮我解释这段 ISCB 脚本的逻辑。
```

### 重构已有脚本

```text
帮我优化这段 ISCB 脚本，可读性优先。
```

### 说明具体平台上下文

```text
请生成一个 ISCB 脚本。
这是数据集成方案的转换脚本，直接用 src / tar。
```

## 3. 什么时候要求校验

如果你只是想先拿到脚本草案：

- 不必要求校验

如果你希望先检查一轮函数、命名空间和基础约束：

- 要求“静态校验”

如果你希望确认脚本能通过真实 runtime 编译：

- 要求“编译校验”

如果你希望拿固定输入实际跑一遍：

- 明确要求“运行验证”

推荐说法：

```text
请生成脚本，先不要保存，也不要运行，只做编译校验。
```

## 4. 什么时候只会拿到参考脚本

下面这些情况，skill 会收敛成“参考脚本 + 限制说明”：

- 你明确要求平台层函数，但没有给资源别名
- 你说是自定义 API / WebAPI 脚本，但没有给实际参数定义
- 你要求查询或写入平台资源，但没有给连接上下文
- 你希望使用 `src` / `tar` / `$process` / `#request`，但没有明确脚本所在节点

推荐把这些信息尽量说清楚：

- 脚本运行在哪个节点或资源里
- 可用的资源别名
- API 参数名或请求对象结构
- 是否需要保存
- 是否需要校验

## 5. 一句话原则

默认直接按你的变量和数据结构生成；是否校验、是否运行、是否保存，由你明确决定。
