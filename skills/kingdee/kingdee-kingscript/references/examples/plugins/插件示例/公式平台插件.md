# 公式平台插件函数案例集

## 职责与入口

`IFuncParamInputFormPlugin` 继承 `IFuncParamEditor`，用于函数的动态参数页。`getFuncInfo()` 与 `getDesignerParameter()` 是读取父容器传入的当前函数/设计器上下文的默认方法，可返回空；它们不是函数注册工厂，也不是表单参数构造入口。不要用这两个 getter 新建并返回一套自定义配置。

| 需要的能力 | 真实入口 |
|---|---|
| 函数名、标题、分类、说明、表达式、参数页 | `IFormulaFunctions.getAllFuncNames/getFuncCaption/getFuncCategory/getFuncDesc/getFuncFormula/getParaFormId` |
| 判断函数归属与运行求值 | `existFunction/evalFunction` |
| 让设计器显示函数 | `FormulaDesignerParameter.addFormulaFunctions(functions)` |
| 让运行引擎执行函数 | `FormulaEngine.registerFunctions(functions)`，在项目确认的初始化入口注册 |
| 参数页校验与输出表达式 | `IFuncParamEditor.checkSetting(StringBuilder)/getSetting()` |

设计期元信息注册不会自动完成运行期注册。实际 `FormulaEngine.registerFunctions` 向进程级实现列表追加，不自动去重；不要在每次绑定或每次求值前重复注册。集群节点/类加载器的初始化和发布由项目管理。

## 含税金额与跨单据函数实现

把下一代码块保存为同一脚本工程中的 `formula-functions.ts` 共享模块。它不作为表单插件挂载，不在加载模块时自行查库或注册。调用者在已有设计器参数上调用 `addFinanceFunctionsToDesigner`，并在真实初始化入口调用一次 `registerFinanceFunctions`；`FinanceFormulaFunctions` 的实际脚本对象到 Java 接口桥接仍须目标平台验证。

- `CALC_TAX_AMOUNT(amount, taxRate)`：两个必填 BigDecimal 参数；税率13表示13%，按 `amount × (1 + taxRate / 100)` 计算，不自动增加金额舍入规则。参数说明由 `getFuncDesc` 提供，真实接口没有原示例的 `FuncParam.setDataType` 注册链。
- `CROSS_BILL_QUERY(entityName, queryField, filterValue[, aggregateType])`：保留目标单据、字段、可选过滤值、单值/汇总能力。三参数使用 `SUM` 是本例继承的默认配置，第四参是本例明确增加的模式协议；空模式表示单值，非空可选 `SUM/AVG/MAX/MIN/COUNT`，不是平台统一约定。
- 四实体候选为 `pm_purorderbill/sm_salorder/im_inbill/ap_paybill`；默认 `pm_purorderbill/totalamount/SUM`。这些是示例选项，不能证明实际实体、字段或当前用户查询权限。
- 原配置没有定义过滤字段、比较符、组织范围、空结果/多行单值含义。实际查询通过 `CrossBillExecutor` 注入，由项目依据已确认的业务合同实现；缺失执行器明确失败，不返回0假装完成。执行器要按当前调用者核权限，不能把一次用户/租户上下文长期捕获到全局注册函数中。

```typescript
import { BigDecimal } from "@cosmic/bos-script/java/math";
import { IFormulaFunctions } from "@cosmic/bos-core/kd/bos/formula/platform/api";
import { FormulaDesignerParameter } from "@cosmic/bos-core/kd/bos/formula/platform/builder";
import { FormulaEngine } from "@cosmic/bos-core/kd/bos/formula/platform/engine";

/** 设计器示例选项；实际实体、字段和权限仍由查询执行器核验。 */
export const CROSS_BILL_ENTITIES: ReadonlyArray<string> = [
  "pm_purorderbill", "sm_salorder", "im_inbill", "ap_paybill"
];
export const CROSS_BILL_AGGREGATES: ReadonlyArray<string> = ["SUM", "AVG", "MAX", "MIN", "COUNT"];
export const FORMULA_HELP_URL = "https://vip.kingdee.com/knowledge/502154811806897920";

/** 空 aggregateType 表示原需求中的单值取数，非空只接受五种汇总；filterValue 是值，不能当 SQL。 */
export interface CrossBillConfig {
  entityName: string;
  queryField: string;
  filterValue: string;
  aggregateType: string;
}

/** 真正取数由已授权业务实现提供；必须逐次核权限/字段/过滤语义，不能捕获用户或租户身份长期复用。 */
export type CrossBillExecutor = (request: Readonly<CrossBillConfig>) => BigDecimal;

/** 新建参数面板的示例默认值；重开已有表达式须优先恢复已有配置，不能无条件覆盖。 */
export function defaultCrossBillConfig(): CrossBillConfig {
  return { entityName: "pm_purorderbill", queryField: "totalamount", filterValue: "", aggregateType: "SUM" };
}

/** 同时供参数面板和求值入口校验；这不是权限或真实字段存在性检查。 */
export function crossBillConfigError(value: CrossBillConfig): string | null {
  if (CROSS_BILL_ENTITIES.indexOf(value.entityName) < 0) return "目标单据不在本例允许范围内";
  if (!/^[A-Za-z_][A-Za-z0-9_]*(\.[A-Za-z_][A-Za-z0-9_]*)*$/.test(value.queryField)) return "查询字段须为字段标识或字段路径";
  if (typeof value.filterValue !== "string") return "过滤值必须是字符串";
  if (value.aggregateType !== "" && CROSS_BILL_AGGREGATES.indexOf(value.aggregateType) < 0) return "汇总方式无效";
  return null;
}

/** 返回可供设计器插入/预览的表达式；只预览表达式，不执行跨单据查询。 */
export function buildCrossBillExpression(value: CrossBillConfig): string {
  const error = crossBillConfigError(value);
  if (error != null) throw new Error(error);
  return "CROSS_BILL_QUERY(" + [value.entityName, value.queryField, value.filterValue, value.aggregateType]
    .map(item => JSON.stringify(item)).join(", ") + ")";
}

/** BigDecimal 精确含税金额；不暗加两位舍入，税率 13 表示 13%。 */
export function calculateTaxAmount(amount: BigDecimal, taxRate: BigDecimal): BigDecimal {
  if (amount == null || taxRate == null) throw new Error("金额和税率不能为空");
  return amount.multiply(BigDecimal.ONE.add(taxRate.multiply(new BigDecimal("0.01"))));
}

/**
 * 函数元信息和运行求值实现。设计器和运行期分别注册；构造不注册、不查询数据库。
 * 跨单据执行器缺失时明确失败；不是按空结果成功，不擅造 QFilter 或组织权限范围。
 */
export class FinanceFormulaFunctions implements IFormulaFunctions {
  constructor(private readonly crossBillExecutor: CrossBillExecutor | null = null) {}

  getAllFuncNames(): string[] { return ["CALC_TAX_AMOUNT", "CROSS_BILL_QUERY"]; }
  existFunction(name: string): boolean { return this.getAllFuncNames().indexOf(name) >= 0; }
  getFuncCaption(name: string): string {
    this.requireKnown(name);
    return name === "CALC_TAX_AMOUNT" ? "计算含税金额" : "跨单据取数";
  }
  getFuncCategory(name: string): string {
    this.requireKnown(name);
    return name === "CALC_TAX_AMOUNT" ? "财务计算" : "数据查询";
  }
  getFuncDesc(name: string): string {
    this.requireKnown(name);
    return name === "CALC_TAX_AMOUNT"
      ? "必填：Decimal 不含税金额、Decimal 税率百分比；结果为金额×(1+税率/100)，不自动舍入。"
      : "目标单据、查询字段、可空过滤值、汇总方式；空汇总方式表示单值，其他允许SUM/AVG/MAX/MIN/COUNT。实际取数需接入已授权执行器。";
  }
  getFuncFormula(name: string): string {
    this.requireKnown(name);
    return name === "CALC_TAX_AMOUNT" ? "CALC_TAX_AMOUNT(amount, taxRate)"
      : buildCrossBillExpression(defaultCrossBillConfig());
  }
  getParaFormId(name: string): string {
    this.requireKnown(name);
    return name === "CROSS_BILL_QUERY" ? "kdec_crossbill_param_form" : "";
  }

  /** 公式引擎传 Java List；金额参数必须是真实 BigDecimal，不能把 Number 强转当精度保证。 */
  evalFunction(name: string, args: $.java.util.List): BigDecimal {
    this.requireKnown(name);
    if (args == null) throw new Error("函数参数不能为空");
    if (name === "CALC_TAX_AMOUNT") {
      if (args.size() !== 2) throw new Error("CALC_TAX_AMOUNT 需要两个参数");
      const amount = FormulaEngine.getBigDecmialValue(args.get(0));
      const taxRate = FormulaEngine.getBigDecmialValue(args.get(1));
      return calculateTaxAmount(amount, taxRate);
    }
    if (args.size() !== 3 && args.size() !== 4) throw new Error("CROSS_BILL_QUERY 需要三个或四个参数（本例三参默认SUM）");
    // 三参默认 SUM 沿用原配置默认；第四参数是本例扩展协议，不是平台固定参数。
    const request: CrossBillConfig = {
      entityName: this.stringArgument(args.get(0), "目标单据"),
      queryField: this.stringArgument(args.get(1), "查询字段"),
      filterValue: args.get(2) == null ? "" : this.stringArgument(args.get(2), "过滤值"),
      aggregateType: args.size() === 3 ? "SUM" : this.stringArgument(args.get(3), "汇总方式")
    };
    const error = crossBillConfigError(request);
    if (error != null) throw new Error(error);
    if (this.crossBillExecutor == null) throw new Error("CROSS_BILL_QUERY 尚未接入已授权的查询执行器");
    const result = this.crossBillExecutor(request);
    if (result == null) throw new Error("跨单据执行器未返回明确的 Decimal 结果");
    return FormulaEngine.getBigDecmialValue(result);
  }

  private requireKnown(name: string): void {
    if (!this.existFunction(name)) throw new Error("不支持的公式函数：" + name);
  }
  private stringArgument(value: unknown, label: string): string {
    if (typeof value !== "string") throw new Error(label + "必须是字符串");
    return value;
  }
}

/** 只添加设计期函数信息；保留已有函数，不清空平台基本函数。 */
export function addFinanceFunctionsToDesigner(parameter: FormulaDesignerParameter, functions: FinanceFormulaFunctions): void {
  parameter.addFormulaFunctions(functions);
}

/**
 * 注册运行期实现；只能由项目已确认的初始化入口调用一次，不放进表单每次绑定。
 * 当前实际实现追加到进程级列表，不去重；部署多个节点/类加载器的初始化由宿主管理。
 */
export function registerFinanceFunctions(functions: FinanceFormulaFunctions): void {
  FormulaEngine.registerFunctions(functions);
}
```

## 跨单据参数页

第二块保存为 `cross-bill-parameters.ts`，相对导入前面的共享模块。将该 `plugin` 挂到真实动态表单 `kdec_crossbill_param_form`，其四个字段为 `entityName`、`queryField`、`filterValue`、`aggregateType`；其中实体和汇总字段使用 ComboEdit，汇总允许空值（单值模式）。配置普通 `preview`、`help` 按钮且不另外绑定业务操作。

新建参数页在 `afterCreateNewData` 填默认值，`afterBindData` 仅配置四实体/五聚合选项及可见性；字段存在与挂载要在实际元数据核对。预览显示将插入的公式表达式，帮助提示已核实的官方说明地址，不把未执行的查询结果作为预览数值。原示例的虚构帮助路径不作为有效地址沿用。

`checkSetting` 和 `getSetting` 共用校验。所核参数容器在校验失败后仍可能继续取 `getSetting`，所以后者也必须在非法输入时返回空串，不能只依赖前一步返回false。已有表达式的解析、回显和重编辑，需要接上项目真实入口；本例仅展示新建参数页，默认值不能覆盖用户已有配置。配置结果是函数表达式，不能声称任意JSON字符串会被公式平台自动持久化并解释执行。

```typescript
import { AbstractFormPlugin } from "@cosmic/bos-core/kd/bos/form/plugin";
import { IFuncParamInputFormPlugin } from "@cosmic/bos-core/kd/bos/formula/platform/api/funcpara";
import { ComboEdit, ComboItem } from "@cosmic/bos-core/kd/bos/form/field";
import { Control } from "@cosmic/bos-core/kd/bos/form/control";
import { LocaleString } from "@cosmic/bos-core/kd/bos/dataentity/entity";
import { EventObject, ArrayList } from "@cosmic/bos-script/java/util";
import { CrossBillConfig, buildCrossBillExpression, crossBillConfigError, defaultCrossBillConfig, CROSS_BILL_ENTITIES, CROSS_BILL_AGGREGATES, FORMULA_HELP_URL } from "./formula-functions";

/**
 * kdec_crossbill_param_form 的参数配置插件。真实动态表单须有 entityName/queryField/filterValue/aggregateType 字段。
 * entityName/aggregateType 必须是下拉控件，aggregateType 允许空值(单值模式)；有 preview/help 按钮。
 * 选项在绑定后设置；预览只显示表达式，帮助显示已核官方页面地址，不执行查询。
 * 本例初始化仅针对新建参数页；已有表达式恢复由实际表单入口传入并在之后写回，不能把新建默认值当重编辑恢复。
 * getFuncInfo/getDesignerParameter 为接口的上下文getter，本实现不重写它们、不以其返回值注册函数。
 */
class CrossBillParameterPlugin extends AbstractFormPlugin implements IFuncParamInputFormPlugin {
  afterCreateNewData(e: EventObject): void {
    super.afterCreateNewData(e);
    const value = defaultCrossBillConfig();
    const model = this.getModel();
    model.setValue("entityName", value.entityName);
    model.setValue("queryField", value.queryField);
    model.setValue("filterValue", value.filterValue);
    model.setValue("aggregateType", value.aggregateType);
  }

  /** 显式连接参数面板的预览与帮助按钮。 */
  registerListener(e: EventObject): void {
    super.registerListener(e);
    this.addClickListeners("preview", "help");
  }

  /** 只改控件状态与选项，不在绑定后给字段赋值。 */
  afterBindData(e: EventObject): void {
    super.afterBindData(e);
    const choices = (values: ReadonlyArray<string>): ArrayList => {
      const items = new ArrayList();
      for (const value of values) items.add(new ComboItem(new LocaleString(value), value));
      return items;
    };
    const entity = this.getView().getControl("entityName") as ComboEdit;
    const aggregate = this.getView().getControl("aggregateType") as ComboEdit;
    entity.setComboItems(choices(CROSS_BILL_ENTITIES));
    aggregate.setComboItems(choices(CROSS_BILL_AGGREGATES));
    this.getView().setVisible(true, "preview", "help");
  }

  /** 预览表达式或显示帮助地址；界面提示不表示实际跨单据数值已查询。 */
  click(e: EventObject): void {
    super.click(e);
    const key = (e.getSource() as Control).getKey();
    if (key === "help") {
      this.getView().showTipNotification("公式平台配置说明：" + FORMULA_HELP_URL);
      return;
    }
    if (key !== "preview") return;
    const value = this.readConfig();
    const error = crossBillConfigError(value);
    this.getView().showTipNotification(error == null ? buildCrossBillExpression(value) : error);
  }

  /** 校验并写错误信息；容器仍可能调用 getSetting，后者也必须独立拒绝非法输入。 */
  checkSetting(errorMessage: $.java.lang.StringBuilder): boolean {
    const error = crossBillConfigError(this.readConfig());
    if (error == null) return true;
    errorMessage.append(error);
    return false;
  }

  /** 只有合法输入才能返回表达式；非法时返回空串，容器不回传和关闭。 */
  getSetting(): string {
    const value = this.readConfig();
    if (crossBillConfigError(value) != null) return "";
    return buildCrossBillExpression(value);
  }

  /** 文本空值保留为字符串空；必填字段由统一校验拒绝，过滤值空是允许值。 */
  private readConfig(): CrossBillConfig {
    const model = this.getModel();
    const text = (key: string): string => {
      const value = model.getValue(key);
      return value == null ? "" : String(value);
    };
    return { entityName: text("entityName"), queryField: text("queryField"), filterValue: text("filterValue"), aggregateType: text("aggregateType") };
  }
}
const plugin = new CrossBillParameterPlugin();
export { plugin };
```

## API 和验证边界

真实 `FuncInfo` 提供 `setFuncName/setFuncCaption/setFuncCatetory/setFuncDesc/setParaFormId` 等方法；注意 `Catetory` 是实际拼写。参数列表、返回值的约束由函数实现检查，不虚构 `setName/setParams/setReturnType`。`FormulaDesignerParameter` 管理设计器整体配置，未提供这里原先使用的 `setFormId/setDefaultValues/setCustomParam`；专用参数页由 provider 的 `getParaFormId` 决定。

本例按实际 7.0 标签构件的 `bos-formula-platform`、`bos-formula-platform-plugin`、`bos-kscript`、表单和脚本声明核验。`FormulaEngine.getBigDecmialValue`（实际拼写）仅强转 BigDecimal，不能把 JavaScript number 或普通字符串当作隐式十进制转换；null也须由函数明确拒绝。物理声明编译不证明运行环境的聚合模块加载、接口代理与参数容器识别。

完整两模块按实际声明编译零诊断，26项编译产物局部逻辑检查和8项纯JDK BigDecimal算式检查通过。尝试运行真实 `FormulaEngine` 的探针在静态初始化阶段因缺少本地平台配置失败，未进入强转和语法断言；不能记为公式引擎通过。表达式转义仅验证JavaScript JSON往返，目标KScript解析器兼容性尚未验证。

平台验收需覆盖设计器显示两个函数、含税参数与求值、四实体/五模式/空单值配置、特殊字符过滤值、非法输入不关闭、确认插入表达式、已有配置回显以及真实查询权限。当前没有执行公式引擎、数据库查询、真实参数页、脚本挂载或多节点注册；共享模块的单元检查与SDK局部探针应分别报告。

依据：[官方《公式平台应用说明》](https://vip.kingdee.com/knowledge/502154811806897920) 的设计期注册、运行期注册、自定义函数接口与参数页章节；示例代码必须再按目标版本实际声明确认。
