# 优化策略

按实际问题选择最小有效修订，先处理正确性、授权或任务完成回退。以下为候选方法，不要求逐项执行。

| 观察到的问题 | 可用修订 |
| --- | --- |
| 无关任务触发 Skill，或相邻 Skill 描述冲突 | 缩短 description，写明实际任务边界；术语和流程清单移入正文。 |
| Skill 使任务偏离用户意图 | 修正误导性目标或固定流程，保留原需求和必要领域契约。 |
| 有无 Skill 结果相当，加入后增加无用工作 | 合并常识和重复宿主规则；保留可验证的能力增量。 |
| 完成首版后停问，已有授权下重复确认 | 写清完成条件和继续范围；仅在真正缺失授权处停下。 |
| 单一模式需要加载大量其他模式细节 | 把条件细节移入 references，并在入口给出读取条件。短入口不强行拆分。 |
| 真实接口、格式或调用顺序容易误用 | 保留精确参数、合适的示例或可验证脚本；固定顺序只用于确有依赖的流程。 |
| 出现可重复的失败且无法恢复 | 补充对应状态核查、停止或回滚条件，不泛化为所有任务的新门禁。 |
| 输出遗漏用户需要的字段 | 补充相关输出合同或复用模板，不为普通回答强加统一格式。 |

语义不清时先明确结果与条件；并列比较可用表格，有真实依赖时可用编号。没有 Phase/Step、速查、图表或固定版式本身不是缺陷。
