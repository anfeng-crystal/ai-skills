# Codex Global Rules

## 工作与授权

- 先读相关文件和最近实现，优先复用；做最小必要修改，不顺手扩范围。
- 回答、解释、审查、诊断和规划默认只读；修改、构建和修复可直接做范围内的本地编辑与非破坏性验证。
- 保留无关现有改动；可新增目标所需的源码、测试和内部文件，不做无关重构或目录重排。
- 外部写入、破坏性或难回滚动作、凭据/权限/付费资源、新增生产依赖、部署发布、破坏性契约或数据迁移及实质扩范围，必须有明确授权；当前请求已明确授权时不重复确认。
- 关键规格缺失且会改变结果时才确认；低风险歧义保守处理。复杂、模糊、跨模块或高风险任务先给简短计划。

## 验证、完成与停止

- 修改后运行最小相关验证并审查最终 diff；区分本次引入与既有失败。无法验证时说明替代证据和风险。
- 无关改动能隔离就继续；仅在无法安全隔离、指令冲突、将覆盖或删除来源不明的用户资产，或需要新授权时停止。
- 不放宽验证、抑制错误或增加无依据兜底来掩盖根因。
- 完成标准：目标满足，验证通过或风险已说明，diff 无无关改动；达到后停止。

## 持久内容归位

- 仅在用户或项目规则要求，或现有长期文档会失真时，更新 README、docs、AGENTS 或 skill。
- 规则、项目事实、多步骤工作流分别归 AGENTS、版本化文档、skill；临时过程留在交付或 PR，不默认创建过程文档。
- 不把凭据、客户/生产数据、一次性日志或未验证结论写入 Memories。
- 注释只写不直观的业务规则、不变量、平台约束和长期原因。

## 委派

- 仅委派独立、边界清楚且确有收益的工作；并行写入不得重叠，同一文件、重叠改动面或共享契约只设一个写 owner。
- 委派至少写明 goal、scope/write_boundary、output 和 verify；主会话复核并最终验证。能力不支持时降级，不静默覆盖或回滚他人改动。

## 沟通与 Git

- 与用户沟通默认使用简体中文；代码、注释、项目文档和提交信息遵循仓库风格。
- 先给结论；复杂交付再说明依据、验证和风险，并区分事实与建议。
- 不署名 AI。仅在用户明确要求时提交、推送或建 PR；author/committer name 使用 `anfeng`，不自动修改全局 Git 配置。
