# Claude 宿主适配

按当前宿主实际提供的能力选路，不以宿主名称或中转配置推断搜索失效。宿主搜索或取文可用时遵循入口的原生能力优先；有实际不可用、结果不足或不稳定证据时，再选择对应回退。

## 推荐顺序
1. 公开事实和文档使用可用的宿主 web/search；已知来源可直接用宿主取文，无需先搜同一 URL。
2. 原生能力不足时，已知来源用本地 fetch/curl；需要发现来源时，在授权范围内用 `scripts/search-aggregator.mjs` 或 `scripts/brave-search.mjs`。key 仅代表配置存在。
3. 需要真实页面状态或登录态时，复用用户指定浏览器或宿主已连接的会话。
4. 选择本地 CDP 且尚无可用性证据时，先 `check-deps.mjs`；再用 `find-url.mjs`、`cdp-proxy.mjs` 处理需要的页面。
5. 需要编写 CLI/自动化流程时加载 `playwright`；现有宿主能力足够时可继续复用。

## 使用原则
- 已知直接来源不需要重复搜索，但仍优先使用宿主已有取文能力。
- 如果 Claude 搜索不稳且又需要广泛发现候选来源，优先考虑 Brave 后端，而不是卡在宿主搜索上。
- 如果宿主已经能稳定读取网页内容，不要为了统一而强行改走 CDP。
- 当前宿主无法读取所需页面状态或确需原始 DevTools 协议时，在保留用户指定会话的前提下使用本 Skill 的本地脚本。
- 重复翻页、滚动加载或导出时，复用可用的浏览器执行器；需要编写自动化代码才按 `playwright` 的入口处理，保留所需会话。
- 宿主缺少浏览器工具时，可以继续做来源矩阵和访问方案；只有明确需要真实页面状态时才要求本机打开 CDP。

## 典型路由
- 最新事实核验：
  用当前可用的宿主检索/取文，再按实际缺口选择直接来源或授权后端，回到来源页核验。
- 登录态页面：
  先核实并复用已授权登录态；确需用户本人登录或人机校验时才请求接管。选择本地 CDP 时才用 `find-url.mjs` / `cdp-proxy.mjs` 接入现有 tab。
- 动态 SPA：
  用用户指定或宿主已连接的浏览器观察；当前能力不足时才补用 CDP 或 `playwright`，不丢失所需登录态。

## 输出要求
- 记录实际来源和获取路径；只有回退或工具限制影响结论时说明原因，不要求附逐工具的未使用清单。
