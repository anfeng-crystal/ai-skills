# 继承与差量规则

实体链和表单链必须分别按各自 `fparentid/finheritpath` 解析；编码相同不代表可共用一条链。

## 执行器解析

1. 从目标单元读取有序 `InheritPath`，用 `ParentId` 补足末端父节点；
2. 按 `fid` 加载固化标准记录，近祖先身份和属性覆盖远祖先；
3. 业务 `action=edit/reset/delete` 节点用 `oid` 映射到祖先 `Id/PkId/Key`；
4. 由有效 ParentId 解析语义父容器，而不是用 XML 顺序或控件名称猜；
5. 报告命中的每个模板编码、fid 和 fdata SHA-256。

只有 `_r*` 登记而没有定义内容的祖先不能提供节点合同，命中即阻塞。业务祖先不在标准快照时交 `kingdee-metadata-analyzer` 查询目标现状。

## 写入语义

- 修改已有覆盖：只改差量节点中的批准属性；从祖先继承的属性可作为允许合同，但 `unset` 只能删除当前差量中实际存在的属性。
- 恢复继承：`restore` 只移除 `action=edit/reset/delete` 且 `oid` 已命中实际祖先的目标层差量节点；缺少或过期 `oid`、缺少祖先定义时先补证，不把直接删除当作恢复。不得复制祖先值模拟恢复。
- 删除：只针对业务完整节点；继承差量不能按完整节点删除。
- 不得修改元数据单元自身的 `ParentId/InheritPath`，除非用户明确要求改变继承关系且已有平台流程与回导证据。

官方[单据页面业务属性](https://vip.kingdee.com/knowledge/234691132842907136?productLineId=29&isKnowledge=2&lang=zh-CN)（核验于 2026-09-26，正文未标最低版本）说明扩展/继承在运行期叠加差异化元数据，源单修改仍会影响下游。这支持保留继承关系；具体 `action/oid` 写法来自目标包及祖先快照，不能从功能介绍推造 XML。上述阻断是执行器的证据边界，不是平台禁止修复孤立差量。
