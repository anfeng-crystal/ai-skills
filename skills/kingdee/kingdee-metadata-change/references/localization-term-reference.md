# 多语言与术语变更规则

四个层独立处理：`entity_l`、`form_l`、`entity_term`、`form_term`。实体名不能写到表单侧，术语不能与普通多语言行合并。

`localization-term-contracts.json` 保存目标环境实际侧表列、值形态、locale 集合和行数；完整标准记录中保留每个模板/祖先的实际侧表行。`zh_CN` 只是一个 locale，不能默认代表全部语言。

## 开发基准语言

[以英文基准语言开发](https://vip.kingdee.com/knowledge/844897929361110528?productLineId=29&isKnowledge=2&lang=zh-CN)（帮助中心，更新于 2026-09-17，2026-09-26 已读正文）的变更记录明确：从 **8.0.10** 起支持配置英文基准语言。核对目标版本、开发服务参数及对象实际基准语言，再决定元数据中的语言值；不能把这项能力用于只有 7.0 证据的环境。

该参数只影响设置后新建、扩展、继承、复制产生的对象，历史对象继续按原语言处理。英文基准对象的其他语言由翻译工作台/翻译平台维护；运行时按当前环境语言、系统默认语言、开发基准语言逐层回退。此规则解释语言语义，不提供 DYM/DYMX 标签或侧表写入合同，仍按下文核对实际包。

## 修改已有行

- 按 `kind + Number + Id/PkId + LocaleId` 唯一定位平台包中的现有 wrapper；
- 只改基线中实际存在的标量属性，例如 `Name`；
- `Id/PkId/LocaleId/Number` 属于身份/关联，不按普通属性改；
- 变更实体或页面名称时分别对账对应侧表，不能只看到 DYM 主文件就声明语言已同步。

## 新增或删除行

数据库标准行只证明侧表形态；新增 locale/term 还需目标包中对应的 DYM/DYMX 序列化与关联依据。依据完整时按 [本地新增](local-addition.md) 在本地构造并验证引用；依据不足仅暂停该部分并补查，不因身份尚未平台生成而阻塞其他字段。现有候选脚本不能独立证明侧表合同完整；删除需平台支持和完整语言影响确认。标准链没有某 locale 行是 `confirmed-absent`，不授权自动复制其他语言。
