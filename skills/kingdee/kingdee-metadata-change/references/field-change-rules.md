# 实体与字段变更规则

删除子树引用与继承字段的复核依据见[云端知识](https://chatgpt.com/space/page_39a9515828b88191a49edd3efba88b2a)；关键变更门禁继续按本文执行。

## 自动定位

字段必须在目标 `EntityMetadata` 中按唯一 `Key/Id/oid` 定位。继承差量的 `oid` 由实际实体祖先链还原；字段类型、XML 父节点、属性和值形态来自 `entity-types.json`，不按名称猜标签。

页面上的标题、顺序、宽度、显隐和锁定不是实体字段属性，转到实际 `FormMetadata` 控件。一个需求同时新增字段和列表列时，合同包含两个独立节点，执行器自动验证绑定关系。

## 新增与换型的类型选择

新增或明确要求换型时，先确认业务含义、单值/多值、存储内容和交互需求，再从目标包、同版本声明或精确 profile 确认类型。下表用于定位候选，不是跨版本字段白名单；仅改标签或布局时保留既有类型，不据中文名称批量换型。

| 业务需要 | 候选与核对重点 |
|---|---|
| 单行、多行、长文本或富文本 | 分别核对 `TextField`、`TextAreaField`、`LargeTextField` 及目标支持的富文本类型/编辑器。长度、换行和富文本格式分别判断，不因长度超过某个经验阈值就选大文本，也不把富文本静默改成普通文本。 |
| 整数计数或普通小数 | 计数与计量数量分开；按实际数值范围和小数需求核对 `IntegerField`、`BigIntField` 或 `DecimalField`，不能仅凭名称“数量”选择类型。 |
| 业务金额或每单位价格 | 分别核对 `AmountField`、`PriceField` 及币种、计算口径；金额不限于多行求和，“报价”也不必然是单价。 |
| 带单位的计量数量 | 核对 `QtyField` 与实际单位字段的绑定及精度来源；已有或继承的 `UnitField` 能满足时复用，不为补齐模板自动新增单位、物料或换算功能。 |
| 普通比率或平台汇率联动 | 普通录入/展示比率可核对 `DecimalField`；需要汇率联动时核对 `ExchangeRateField` 的源/目标币种、汇率类型、日期、牌价关联。名称“汇率”不能代替这些语义，已有依赖可从目标元数据取证。 |
| 日期、日期时间或区间 | 分别核对 `DateField`、`DateTimeField`、`TimeField` 等目标类型及时间信息保留；区间按完整复合结构处理，例如 `DateRangeField` 的起止字段与列映射，不能只改一个显示控件便宣称存储合同完整。 |
| 单选/多选引用、单据引用或引用属性 | 核对 `BasedataField`/`MulBasedataField` 的实际引用对象与基数；组织、用户、辅助资料、关联单据及属性携带分别查对应合同。“员工/负责人”不直接等同用户；`RefBillField` 不因外观相似换成基础资料或文本，`BasedataPropField` 要定位所跟随字段及真实属性路径。 |

长度与精度须分清实体存储、控件显示及单位/币种策略，合法范围和可写属性按[属性适用性](property-applicability.md)核对；不把其他类型的属性、一个样本的数值或资料包预设当作通用默认，也不把有 `Precision/Scale` 属性解释为任意组合均合法。

选定类型后核对其实际必需的选项、单位/币种、引用目标、多选关系表或伴随节点，保留完整关联；缺项先从可信目标材料补证，不能为通过本地检查而静默退成普通文本/小数或删掉依赖。选择控件与实体选项存储分别定位；`RadioField`/`RadioGroupField` 等组合按目标完整节点核对，不把资料包的禁用标记套到必需的伴随节点。资料包 CLI 参数和命名约定不能直接当作元数据属性或当前执行器能力。

## 修改已有字段

- `modify` 只改已存在标量属性；字段 `Id/PkId/Key/MasterId/ParentId` 不变。
- 新属性先核对精确“字段节点类型 + ModelType + XML 父节点”的适用性；样本出现不等于本次应配置，规则见 [属性适用性](property-applicability.md)。目标类型不支持必录时不添加 `MustInput`，也不从接口必填推导实体必录。
- 布尔、数值、颜色和尺寸遵守实际值形态；复杂子树不能通过 scalar set 拼装。
- 类型、引用对象、集合/分录归属、物理列或默认值语义变化前，调用 `kingdee-metadata-analyzer` 盘点表单、列表、移动布局、报表、插件和数据消费者。

## 选择项的显示与存储

下拉等选择字段分别核对显示标签、实际存储值、顺序和默认值，按目标字段的真实结构修改。只改标签时保留原存储值及未涉及项；截图当前选中值不能证明默认值或完整候选集，不据此补造选项或编码。

更改存储值或移除正在使用的选项前，核对既有数据、规则/过滤条件及接口消费者；数据迁移交 `kingdee-sql-and-data` 按授权处理。删除影响当前默认值时先解决该冲突，不擅自选第一项作为新默认；未涉及的默认值和顺序保持原状。

## 新增字段

默认按 [本地新增](local-addition.md) 构造字段及新身份；本地候选用 `verify-candidate` 检查，平台导出候选可用 `verify-platform-candidate`：

- 基线不存在、候选恰有一个完整字段节点；
- 节点类型、模型和父节点有标准完整实例；
- 精确身份合同的共有身份属性齐全；
- 若同时新增控件，控件绑定值解析到该字段，字段类型—控件类型组合已观察；
- 移除批准新增节点后无其他结构差异。

不要求先在平台创建字段或证明平台内部身份算法。基于实际格式生成的新身份仍须检查冲突、引用，并在已授权目标环境导入验证。

## 删除、移动和存储

- 删除前检查整个待删 XML 子树的身份与剩余节点引用；执行器覆盖包内标量引用及已观察的规则 `Fields/FieldId/Id`，随子树一起删除的内部引用不阻断。表达式、其它复合引用及包外消费者继续由 analyzer 取证，不能把扫描通过当作引用全集已清空。
- 继承字段差量用 `restore`，不删除或复制父字段。
- 改分录/父实体必须用 `move`，新父节点可解析且不成环；涉及存储或物理 DDL 时另交 `kingdee-sql-and-data`。
- `mainentityinfo` 只验证主实体映射和能力，不代替普通字段定义与物理列证据。
